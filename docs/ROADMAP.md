# VortexCue 精简路线图

> 当前阶段：M0A OLED 物理原型  
> 原则：先证明体验，再增加播放器能力。

## 工作约束

- 同一时间只推进一个阶段；
- 每个阶段必须产生可运行、可验证的结果；
- 未通过阶段门，不提前建设后续架构；
- 默认单模块、少依赖、无账号、无网络；
- 新功能必须直接改善夜间字幕消费体验。

## M0A：OLED 物理原型

要回答：真实 OLED 上能否做到背景视觉消失，同时字幕仍可舒适阅读？

范围：

- 纯黑 Compose 表面；
- 沉浸模式和黑色启动背景；
- 窗口亮度与字幕灰阶分别调节；
- 一组真实长度的校准字幕；
- 控制层可完全隐藏，屏幕保持唤醒。

完成条件：

- Debug APK 可安装；
- 至少一台 OLED 真机无明显背景和系统栏泄漏；
- 用户能找到“刚刚可读”的字幕亮度；
- 隐藏控制后没有常驻装饰和持续动画。

本阶段不做：媒体播放、文件导入、字幕解析、设置持久化。

## M0B：60 秒完整体验

要回答：听真实内容时，微光字幕是否比普通播放器更适合持续使用？

范围：

- 一段可合法分发的 3–5 分钟内置音频及同步字幕；
- 播放、暂停、快退与字幕同步；
- 普通介绍页进入微光模式；
- 复用 M0A 亮度校准。

完成条件：

- 从启动到播放不需要选择文件或配置服务；
- 暂停、恢复和快退后字幕正确；
- 至少完成三次完整样片的暗室体验记录，并确认体验者愿意继续尝试自己的内容。

本阶段不做：后台服务、媒体库、云服务和专属项目格式。

## 阶段门：是否进入播放器 MVP

满足以下条件再继续：

- OLED 背景消失效果稳定可感知；
- 字幕最低可读亮度明显低于普通播放器；
- 体验者愿意在目标场景重复使用；
- 系统干扰、耗电和低灰显示问题处于可接受范围。

若未满足，先调整显示和交互；不以增加格式或云功能补偿核心体验。

## M1：本地播放 MVP

只建立一条完整用户路径：

```text
选择本地音频或视频
  -> 选择 SRT
  -> 播放并同步字幕
  -> 进入微光模式
  -> 调整字幕偏移
```

范围：Media3、Storage Access Framework、SRT、字幕时间轴、后台播放与系统媒体控制。LRC、多媒体库、字幕编辑和项目 ZIP 不在本阶段。

## 后续候选

按真实使用证据逐项选择，而不是预先排期：

- LRC 与更多字幕格式；
- 视频多音轨和内嵌字幕；
- 项目保存与 `.vtxsub`；
- 云 ASR 与翻译；
- FFmpeg fallback；
- TransVortex 格式互通。

每个候选进入开发前，都需要一个现有能力无法解决的真实样本或重复用户需求。
