# M0A OLED 物理可行性验证

> 状态：首轮 OLED 真机验证通过
> 验证日期：2026-08-06
> 阶段：M0A OLED 物理原型

## 结论

首轮暗室真机测试支持 VortexCue 的核心假设：在真实 OLED 手机上，纯黑背景可以保持视觉上的消失，同时以低灰阶显示可读字幕。窗口亮度和字幕灰阶可以分别调节，控制层隐藏后只保留黑底和字幕。

这证明了产品方向的基本可行性，但还不是完整的 M0A 阶段验收，也不代表已经得到客观亮度、功耗或长期残影结论。

## 验证环境

- Android 单模块 Kotlin + Jetpack Compose 原型；
- JDK 17、Gradle Wrapper 9.5.0、Android SDK 37；
- Debug APK：`app/build/outputs/apk/debug/app-debug.apk`；
- 真机：Vivo `V2458A`，物理分辨率 `1260 x 2800`；
- 通过 USB 调试安装并启动，未使用模拟器替代真机测试。

## 验证内容

1. 构建并安装 Debug APK；
2. 启动全屏黑底字幕页面；
3. 在暗室观察纯黑背景与低灰阶字幕；
4. 调节窗口亮度和字幕灰阶；
5. 点按屏幕隐藏校准控制；
6. 检查应用进程、前台 Activity 和崩溃日志。

## 观测结果

- 应用可以稳定启动并保持在前台；
- 黑色背景没有可见的常驻背景光；
- 字幕在低灰阶下仍然可以被观察到；
- 提高窗口亮度和字幕灰阶后，字幕亮度明显增加，而背景仍保持纯黑观感；
- 控制层可以通过点按隐藏，隐藏后没有常驻装饰；
- 屏幕保持唤醒，系统栏没有出现在校准画面中；
- 修复了首版在部分 Android 设备上的启动崩溃：系统栏控制改为在 Compose 内容建立后访问 `decorView.windowInsetsController`。

## 当前校准参数

原型将两个变量分开控制：

- 窗口亮度：`1%..25%`，通过 Android 窗口的 `screenBrightness` 请求屏幕亮度；
- 字幕灰阶：`RGB 2..32`，以相同的 R、G、B 值生成字幕颜色。

“拉满”表示当前原型范围的上限，不等于设备系统亮度 100% 或 8 位 RGB 的 255。实际面板亮度仍可能受自动亮度、厂商显示策略和系统辅助功能影响。

## 尚未验证

- 多台不同 OLED 面板上的一致性；
- 仪器测量的黑位、最低可读亮度和亮度曲线；
- 长时间显示后的残影、烧屏风险和温升；
- 自动亮度、额外变暗、护眼模式等系统设置的干扰；
- 续航影响；
- 真实音频播放与字幕同步。

## 下一步

1. 在同一设备上记录 `RGB 2/4/8/16/32` 与不同窗口亮度组合的最低可读点；
2. 重复至少三次暗室测试，并记录用户主观舒适度；
3. 在另一台 OLED 设备上复测，确认校准范围不是单一机型特例；
4. 通过 M0B 内置音频和同步字幕验证持续使用体验；
5. 在进入 M1 前补充设备级亮度、功耗和长时间显示记录。
