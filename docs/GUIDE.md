# VortexCue / 荧荧产品指南

> 状态：当前唯一的产品与实施指导
>
> 当前阶段：OLED-first 本地播放器与选择性内容库
>
> 更新时间：2026-08-10

荧荧是一款围绕 OLED 微光体验设计的本地播放器。它先让用户可靠地找到、整理和播放自己的内容，再让手机在睡前、暗室或宿舍等环境中逐渐退场。

同步字幕是重要能力，但不是播放或进入微光的前提。音频和视频都属于可发现内容；视频比音频更私密、更容易混入无关素材，因此必须由用户明确选择后才进入播放器的内容库。

## 产品原则

- **OLED-first**：纯黑不是深色皮肤，而是界面的基础材料。亮度、色块和常驻元素都需要理由。
- **本地优先**：不依赖账号、网络或云端目录。文件仍留在原位置，应用只保存授权、索引和用户选择。
- **发现不等于收录**：扫描可以主动，进入内容库必须保守。用户决定留下什么，也可以随时移出或恢复。
- **播放器先完整**：内容能找到、队列能控制、后台能继续、状态能恢复，微光才有成立的基础。
- **字幕可选**：有字幕时提供同步阅读；没有字幕时照常播放并进入纯黑微光。
- **界面会退场**：普通界面清楚克制，微光只在明确交互后短暂出现控制。
- **保持简单**：围绕内容、播放和微光解决真实问题，不预建复杂分类和工程层级。

## 应用结构

```text
首页
├─ 用户选择显示的文件夹
├─ 用户选择显示的播放列表
├─ 搜索
└─ 当前播放

内容管理
├─ 待整理
├─ 已收录 / 已忽略
├─ 首页内容选择
└─ 扫描范围

普通播放器
├─ 进度与播放控制
├─ 队列、播放模式与睡眠定时
├─ 字幕与同步调整
└─ 进入微光

微光
├─ 沉浸锁定
└─ 临时操作

显示
├─ 微光校准
└─ 字幕外观
```

首页左上角保持空白，不重复显示应用名称，也不使用“资料库”之类的页面标题。首页不展示最近加入、来源状态、专辑或歌手入口；这些内容会制造维护感和音乐商店感，却没有帮助用户更快回到自己整理好的内容。

系统媒体库、授权文件夹和单独打开记录属于低频的扫描范围，只在内容管理深处出现。显示设置也不与当前播放或内容来源混在一起。

## 内容管理

### 三段式流程

内容进入应用遵循同一条路径：

```text
扫描发现 -> 候选整理 -> 收录或忽略
```

- 系统扫描分别请求音频和视频访问，已有一种权限时仍允许补充另一种权限；
- 用户选择文件夹后，递归发现可播放媒体和同目录字幕；
- 单独打开文件是明确的用户动作，可以直接收录；
- 扫描结果先进入“待整理”，不会直接进入首页、搜索或播放队列；
- 音频候选默认预选，视频候选默认不选并显示时长、分辨率、体积和字幕匹配情况；
- 已忽略内容在之后刷新时不重复打扰，用户可以在管理页恢复；
- 从已收录中移出的内容转为忽略，不删除原文件，也不继续残留在播放列表中。

文件夹扫描发现与媒体同目录、同主文件名的 SRT、LRC、WebVTT、ASS 或 SSA 字幕。用户收录对应媒体时保存关联；没有匹配字幕不影响收录和播放。

### 内容集

应用不把歌曲、专辑、歌手、文件夹和来源并列成一排固定分类。第一阶段只保留两种真正可管理的内容集：

- **文件夹**：来自本机目录结构，自动反映用户已经做过的文件整理；
- **播放列表**：由用户手动组织，与这一次实际播放的队列分开。

两者在首页承担相同角色：都是可以打开和整体播放的快捷入口。收录内容后，用户自行选择哪些内容集出现在首页；这是首页可见性选择，不叫“固定”。

专辑和歌手来自媒体标签，可能缺失、错误或在视频内容中没有意义。它们可以继续辅助标题显示与搜索，但暂不作为顶层组织方式。未来只有在真实本地资料库中证明稳定有用，才增加相应视图。

### 播放队列

内容集是长期组织，播放队列是本次播放顺序。从文件夹、播放列表或搜索结果开始播放都会形成明确队列。用户可以查看和调整接下来内容、移除队列项、下一项播放、添加到队列，并使用随机、循环和倍速。

## 普通播放器与视频

普通播放器承担所有明确、可见的操作：标题与必要元数据、可拖动进度、上下项、快退快进、队列、播放模式、倍速、睡眠定时、字幕选择与偏移，以及进入微光。

睡眠定时至少支持常用分钟数、当前内容结束后停止、剩余时间与取消。播放状态由后台 MediaSession 持有，离开界面或关闭屏幕后仍可继续，并与通知、锁屏、耳机和蓝牙控制同步。

内容模型从现在开始明确区分音频和视频。当前播放内核可以打开视频容器并播放其中音轨，但普通播放器还没有视频画面；正式的视频表面是后续播放器能力，不能由“扫描到了视频”假装已经完成。未来加入画面时，微光仍是用户主动进入的独立状态，不强迫所有视频采用沉浸式播放。

## 微光

微光不是普通播放器隐藏几组控件后的结果，而是独立的沉浸状态：

- 有字幕时为纯黑背景和当前字幕；
- 无字幕或字幕间隙时为纯黑背景；
- 默认处于沉浸锁定，普通单次触碰不弹出操作栏；
- 左、中、右区域双击分别执行快退、播放或暂停、快进；
- 长按进入临时操作，数秒无操作后重新锁定；
- 临时操作只保留进度、基础控制、睡眠定时、字幕偏移和返回普通播放器。

首次进入微光前进行一次短校准，用真实纯黑背景和示例文字直接预览窗口亮度、文字亮度与控制亮度。字幕字号、位置和排版独立设置，不混入微光亮度校准。

微光锁定只防止应用内误触，不冒充系统锁屏或 AOD，也不拦截来电、闹钟和系统安全行为。

## 视觉语言

- 全局使用 OLED 纯黑背景，层级主要依靠排版、间距、透明度和细分隔；
- 不使用大块强调色、彩色卡片、渐变背景和装饰性发光；
- 品牌黄色只用于当前选择、进度、焦点和少数关键动作；
- Logo 只出现在启动、关于或真正需要品牌识别的时刻，不支配每个页面；
- 主界面不反复提示应用名称或功能说明；
- 页面与系统栏尽量融合，减少套用系统模板的感觉；
- 动效以淡入、淡出和克制的位置变化为主；
- 普通界面保持清晰和足够触控面积，低亮度只属于微光。

每个常驻元素都应回答：它是否帮助用户找到内容、判断状态或完成当前操作？如果不是，就移除或延后出现。

## 当前边界与下一步

当前不进入范围：在线目录、推荐与社交、账号和云同步、ASR、翻译、字幕编辑、在线字幕搜索、均衡器和复杂音效系统。

近期实施顺序保持简单：

1. 完成选择性扫描、内容集首页和管理闭环；
2. 用真机验证大量音视频候选、权限组合、文件夹字幕匹配和持久化；
3. 继续打磨普通播放器与微光的连续体验；
4. 设计并实现正常播放器中的视频画面，再决定视频进入微光时的具体表现。

现有工程继续保持单一 `app` 模块、Kotlin、Compose 和 Media3。播放器以后台 Player / MediaSession 为唯一播放真相；媒体文件不复制到应用目录，只有可重建索引、用户选择和小型字幕缓存可以持久化。

## 工程边界

工程保持单一 `app` 模块，不为目录整齐提前拆分 Gradle 模块。Kotlin 包按职责组织：

```text
app       Activity、应用组合根与跨功能导航
core      共享模型与存储格式
library   媒体发现、内容决策、播放列表与持久化
playback  MediaSessionService、会话恢复与睡眠定时
subtitle  字幕读取、解析、时间轴与缓存
ui        首页、播放器和主题
```

- `PlaybackService` 内的 Player / MediaSession 是播放状态的唯一真相；
- `app` 负责连接系统入口和功能状态，不重新实现内容库或播放规则；
- 内容库状态由独立 state holder 持有，扫描和配置变更不放回 Composable；
- 可独立判断的内容决策保持为纯函数并使用 JVM 单元测试覆盖；
- 包边界用于约束依赖方向，只有出现真实构建或复用需求时才增加 Gradle 模块。
