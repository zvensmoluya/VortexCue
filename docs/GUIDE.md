# VortexCue 产品与实施指南

> 本文是当前 UI、信息架构和实现边界的最高产品规格。
> `docs/reference/UI_LAYOUT_DESIGN.md` 记录布局与交互细节；`docs/reference/布局原型.html` 仅保留结构参考，不代表视觉风格。
> 长期领域背景见 [`DOMAIN_CONTEXT.md`](DOMAIN_CONTEXT.md)。

VortexCue 是 Android-first、OLED-first、sleep-first 的本地内容播放器。核心价值是“内容继续，屏幕退场；需要视觉时只显示当前同步文字”。字幕不是播放前置条件，但在 Normal Player 与 Glow 中是最小、可读、可退出的视觉内容。

## 1. 应用壳层

一级页面固定为四个：

```text
歌单 | 播放列表 | [骨白荧荧 Logo：Import Hub] | 配置 | 设置
```

Logo 是动作，不是第五个页面；点击只打开 Import Hub，不改变当前 Tab。歌单页承担默认进入位置，但 UI 不使用“首页”命名，也不再出现 Home、今晚、发现或来源一级入口。

存在 Current Queue 时，Mini Player 跨四个 Tab 显示。Mini Player 是与底栏连续的全宽播放坞，不复用歌单卡片轮廓；它只显示标题、已播放时间、剩余时间、播放状态标记和播放/暂停，时间直接表达当前播放位置，不另设重复的进度条。播放时状态标记轻微起伏、顶边微光和按钮光晕缓慢呼吸，暂停时归静，缓冲时按钮外显示细弧；出现、退场、切歌与播放图标切换使用短促克制的过渡。播放按钮使用独立圆形承载面，点击播放坞正文只进入 Normal Player，不改变播放状态。它不显示同步文字、Sleep Timer 或额外播放操作。冷启动不恢复 Glow，Glow 只能由当前运行期的 PlayerSurface 明确进入。

应用内视觉令牌：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| Background | `#000000` | 页面与 Glow 背景 |
| Primary text | `#EEF0F4` | 月白主文字 |
| Secondary text | `#A39EAF` | 冷紫灰次要文字 |
| Raised surface | `#17151D` | Bottom Sheet、对话框、控件层 |
| Hairline | `#2A2732` | 细分隔线 |
| Selection | `#282432` | 当前项与选中态 |
| Mascot | `#E8E0D0` | 中央骨白 Logo |

黄色不进入应用内 UI；Launcher 与 Splash 保留既有品牌资源。当前歌单不使用封面、拼贴或文件夹图标，最多 8dp 圆角。普通浏览页允许使用 Raised Surface 与较高文字对比度；极低发光只约束 Glow 等退场阶段。交互控件最小 48dp 触控区，图标按钮必须有 TalkBack 描述；拖动、长按等动作同时提供可访问的替代操作。

## 2. 歌单与全部内容

歌单是用户长期整理和重复进入的内容集合，与物理文件夹和 Source 完全独立。一个 `contentId` 可以加入多个歌单，但同一歌单内唯一；用户歌单和歌单成员均使用手动顺序。每个已收录内容必须至少属于一个真实歌单，删除歌单或移除成员不删除原文件，也不改变已经生成的 Current Queue。

固定系统歌单“默认收藏”是所有收录操作的安全落点，不可改名、删除或参与歌单排序。歌单页不显示页面大标题和搜索。顶部“最近听过”最多横向展示 6 个最近真正从中开始播放的非空真实歌单；默认收藏实际开始播放后也可以进入最近听过。下面“全部歌单”固定以虚拟入口“全部内容”置顶，默认收藏固定其后，再按用户手动顺序展示普通歌单。当前版本仅用排版和 Raised Surface 区分歌单，不提供图标或图片封面。

“全部内容”是所有真实歌单成员按 `contentId` 去重后的聚合视图，按最近加入优先排列，不写入 `playlist` 表，不能成为任何导入或管理操作的目标，也不进入“最近听过”。从“全部内容”点击媒体只以单项替换 Current Queue。歌单详情提供“播放全部”；点击具体内容时用完整歌单顺序替换 Current Queue，并从点击项开始。只有替换成功后才更新歌单最近播放时间。

从普通歌单移除内容的最后一个归属时，内容自动进入默认收藏；删除普通歌单时，其独占内容同样转入默认收藏。归属编辑器不允许最终为空，空选择回退默认收藏。默认收藏中的唯一成员不提供“从当前歌单移除”；彻底移除使用独立“移出内容”，清空全部歌单归属并写入忽略状态。用户之后显式选择同一文件时重新收录，不提供单独的忽略项恢复入口。

内容长按 Bottom Sheet 提供：

- 立即播放；
- 加入播放列表；
- 加入歌单；
- 从当前歌单移除（仅歌单详情）；
- 同步文字；
- 移出内容。

歌单详情右上角提供“整理内容”模式。进入后可以多选、全选，并批量“加入歌单”“移动到”或“从此移除”。“加入歌单”保留内容已有归属并支持多个目标；“移动到”只选择一个目标，把内容从当前歌单移出，但不影响它已有的其他歌单归属；批量移除沿用最后归属回退默认收藏和默认收藏唯一归属保护。全部内容没有来源歌单，只提供批量“加入歌单”。批量关系更新必须在单个数据库事务内完成，并反馈已更新、已存在和受保护数量。

“移出内容”只写入内部忽略状态，不删除原始媒体、不打断当前播放；来源刷新不会再次推荐。用户仍可从系统文件选择器显式选择同一文件，重新收录并立即播放。

## 3. Import Hub 与来源

底栏中央 Logo 打开临时全屏 Import Hub，不改变当前 Tab。流程只有“来源首页 / 来源详情”两层：详情返回来源首页，来源首页关闭后回到原 Tab。首次进入先说明音频发现用途并由“开始查找”请求音频权限；拒绝后不自动重弹，仅保留“再次允许”“选择音频或视频文件”“从其他位置查找音频”。Android 13+ 只请求 `READ_MEDIA_AUDIO`；旧系统即使使用宽泛存储权限，应用也只查询音频。

已授权时先展示持久缓存，并在每次打开 Import Hub 时后台刷新系统音频和已授权文件夹。刷新期间旧结果仍可浏览，显示进度与取消；失败或授权失效时保留旧索引并就地提供重试或重新授权。系统音频和已授权文件夹按扫描边界与规范化相对位置形成稳定来源卡片；路径末尾连续出现明确的音频格式、音质或 SE 变体目录时折叠到作品根，RJ 编号可作为跨内容子目录的强作品边界，其他证据不足的路径保持物理目录分组。卡片显示名称、总数、新增数和示例标题；有新增、较新、偏长音频的位置优先，系统提示目录和全为一分钟内短音频的位置降级到“全部位置”。没有位置元数据时归入“其他音频”，同名位置补充上级名称。

自动发现和文件夹持续扫描都只收录音频。视频只允许用户通过单文件选择明确导入，本轮没有来源级视频发现开关。文件夹扫描会静默登记媒体与外挂字幕的匹配关系：未收录内容只保留来源候选；用户确认收录内容时，全部已匹配字幕立即转为应用自有文字轨；已收录内容后来发现的新字幕也在来源刷新后立即转为自有文字轨。扫描、选择和完成反馈都不显示字幕状态，单个字幕失败不阻塞媒体导入或其他字幕处理。

来源详情默认进入“新增”范围并勾选待添加音频，也可切换“全部”，选择已收录内容追加到其他歌单。明确位于平行 WAV / MP3 目录且除扩展名外文件名相同的待添加音频，初始只勾选 WAV；两份物理文件仍完整展示，用户可以改选 MP3 或同时选择，无法严格配对时维持全部勾选。后台刷新期间，用户尚未修改选择时按相同规则同步新结果；一旦用户手动勾选、全选或取消全选，本次详情不再自动改变选择。列表按标题/文件名自然排序，导入按当前顺序追加；取消勾选不改变待添加状态，只有单项更多菜单的“不再推荐”写入忽略。底部固定显示选择数量、目标摘要和“将 N 项加入 M 个歌单”；成功后停留在来源详情，刷新新增数，不自动播放，并显示添加结果及“查看全部”“完成”。新增范围为空时必须呈现明确完成状态，不能只留下空白列表。

批量导入必须选择至少一个真实歌单并支持多选。从真实歌单详情打开 Import Hub 时，本次会话优先以当前歌单作为来源导入和单文件导入目标，且不覆盖该来源的长期目标偏好；从中央 Logo 等通用入口打开时，来源首次默认选择默认收藏，成功后记住该来源最后确认的目标集合，下次恢复仍存在的目标，否则回退默认收藏。默认收藏为唯一选择时，首次选择普通歌单会替换它，面板必须说明这一行为；之后可以继续多选或显式重新加入默认收藏。目标面板实时显示确认目标数量，可当场新建歌单并自动选中。新内容加入全部目标；已收录内容只做归属并集，不移除原归属，也不重复插入。

单文件音频或视频从歌单上下文进入时直接加入当前歌单，否则加入默认收藏，并立即播放。启动系统文件选择器时 Import Hub 保持原页面和状态；用户取消后原样返回，读取或导入失败时留在原页面显示明确错误，只有成功后才关闭并进入播放。外部 `ACTION_VIEW` 仍只临时播放，不自动收录。来源是扫描授权与刷新边界，不是歌单；设备目录不会复制成真实歌单或额外授权 Source。

## 4. 播放列表

“播放列表”页面只有一个 Current Queue，数据与 Player 的队列对齐。支持选择播放、拖动重排、移除、清空和当前项标识。队列内同一 `contentId` 唯一，重复加入不追加，只提示“已在播放列表”。

队列连续播放、MediaSession、后台播放、耳机/蓝牙控制和 Sleep Timer 是固定行为，不在设置页暴露开关。Sleep Timer 使用停止条件编辑器：时长由小时/分钟滚轮自由设置，也可选择当前内容结束或多项播放列表结束；滚动只编辑，显式开始或重新计时后才生效。编辑器记住本次播放服务中的上次设定时长。已开启状态只显示“已开启”，播放器与 Glow 均不展示剩余时间、预计停止时间或持续倒计时。

## 5. 配置

配置页只有一套完整的 `SyncTextConfig`，顶部切换“翻译模型配置”和“语音识别”。不向用户展示 Scheme、Attempt、Task Queue、Token、Hash 或技术结果详情。内部仍使用稳定配置 ID 关联后台审计与 attempt snapshot。

翻译配置提供协议选择、可编辑的 Base URL、自动发现的模型选择、API Key、目标语言和展示模式。官方示例只展示服务根地址或 `/v1` 地址；用户不需要填写 `/responses`、`/chat/completions` 或其他资源路径，应用根据协议在内部补全。Base URL 或协议变化后静默尝试拉取可用模型，不提供刷新按钮；服务不提供模型目录时仍允许直接填写模型。用户可以发送一个低额度测试请求，确认所选协议、地址、模型和 Key 真正可用。Key 由 Android Keystore 加密保存，Endpoint 必须经过 HTTPS 与主机校验。

ASR 配置先选择提供商，再选择该提供商的模型；OpenRouter 提供 Whisper large-v3 与 Grok STT，并保留可编辑的 Base URL。本项目对 OpenAI 官方提供商当前只开放 Whisper-1，固定使用官方 `/v1/audio/transcriptions` multipart 上传协议，不复用 OpenRouter 的 JSON 音频协议。GPT Transcribe 等只能返回纯文本、不能返回可用时间轴的模型不进入可选列表；未来只有在官方提供时间轴后才重新评估。每个提供商由独立适配器负责请求与响应；用户可以发送一个极短的测试音频确认连接，测试不会创建同步文字结果。

生成自动使用当前配置：已有文字优先翻译，没有文字才执行 ASR；只有多音轨等真实歧义才请求选择。单个 ASR 窗口允许没有语音并以空时间轴继续，整个媒体都没有可用 cue 时明确提示“未检测到可转写语音”，不归因于提供商或网络故障。任务默认只使用非计费网络；等待计费网络许可时就地说明原因，并允许用户仅为本次任务授权。临时网络错误使用共享退避与抖动；设备没有 validated network 时进入可自动解除的等待，而不是要求用户手动重试。同步文字页提供取消与重试，不出现全局任务抽屉。

## 6. 设置

设置只负责 Glow 窗口/文字/控制亮度、字号、垂直位置、预设与首次校准，以及音频权限状态和关于。应用不请求或展示设备视频库权限；系统栏隐藏、队列连续播放等固定行为不做可选项。

Glow 为纯黑、安全 Insets、独立亮度；双击分区、长按临时控制、5 秒退场保持现有行为。Glow 只在媒体实际播放时保持屏幕常亮；暂停后立即释放常亮但保留当前文字，播放结束、播放错误或 Sleep Timer 触发后立即清空全部来源的文字并保持纯黑，由系统按既有超时策略熄屏和锁屏。Glow 返回 Normal Player，再返回原一级页面。

## 7. Player 与同步文字

Normal Player 的主体固定为“上一句弱化 / 当前句主视觉 / 下一句弱化”，不显示假封面。顶栏只保留返回、标题和低频操作菜单；底部只常驻进度、上一项 / 后退 10 秒 / 播放 / 前进 10 秒 / 下一项、速度、Sleep Timer、播放列表和进入 Glow。随机与循环进入播放列表面板，校准不在播放器常驻，字幕时间偏移藏在同步文字面板。

播放器不常驻同步文字“管理”入口：没有文字时，字幕舞台只显示“生成同步文字”；已有可翻译原文时，只在舞台边缘显示翻译图标；动作启动后原位切换为不确定态环形进度，任务入队后切换为带百分比的确定态环形进度。同步文字面板只负责主文字、第二文字、手动文件、恢复自动匹配、生成结果展示和低频时间偏移。启动成功不再弹出确认对话框。手动导入会读取、解析并规范化 SRT / VTT / ASS / LRC，然后发布为应用自有的 immutable revision；成功后的文字轨不再依赖原 URI 或 SAF 权限。Folder 外挂字幕在对应内容被收录且匹配关系已发现时发布为应用自有 immutable revision；资源接管与主/第二文字选择相互独立，播放器不承担正常的候选物化。内嵌文字仍由 Media3 实时播放，仅在生成任务把它作为固定输入时物化 source revision。生成结果完成后自动成为可选文字轨。

## 8. 数据与迁移

Room 当前 schema 为 v10。`playlist.system_role` 唯一标识默认收藏；来源导入偏好和多选目标关系持久保存，目标歌单删除时级联清理。来源卡片由可用音频 locator 的 `sourceId + inferred work root` 动态聚合；作品根只使用 RJ 编号和完整命中的末级技术目录做保守推断，不把设备目录复制为歌单或授权 Source。扫描只更新持久索引，UI 直接观察数据库中的待添加状态，不保留进程内整批 `pendingImport`。

v7→v8 通过自动迁移保留任务、结果和手测诊断数据，v8→v9 手动把旧虚拟文件夹和单归属成员关系迁移为同名多对多歌单。v9→v10 优先把现有同名“默认收藏”提升为系统歌单，否则创建；已收录但零歌单归属的内容按原全部内容顺序迁入默认收藏，现有多归属、播放时间、同步文字和忽略状态保持。迁移会清理旧自动发现且未收录的视频记录，已明确收录的视频保留，后续音频刷新只失效旧音频 locator，不误伤这些视频。v6 及其他不兼容版本仍允许破坏性重建。

重建清理应用私有旧字幕缓存、旧 result/checkpoint VTT、孤立凭据文件和旧的 Home shortcut 数据；保留 Settings、用户原始媒体和 SAF 外部字幕文件。数据库不再把 `lastSurface` 当作启动入口；`PlayerSurface` 只管理运行期 Normal/Calibration/Glow 层级。

导入与生成文字统一使用 `CanonicalTimeline`、`TimelineRevision` 和 content-addressed `TextArtifactStore`。Artifact 位于 `noBackupFilesDir/text_artifacts/<kind>/<prefix>/<id>.bin`，ID 是包含 kind、schema、codec 与 canonicalizer version 的完整二进制 envelope SHA-256。Room 只保存 Artifact metadata、不可变 revision、manifest 和 publication pointer，不保存逐 cue 正文。`TimelineRevisionReader` 一次解码当前 publication 为内存 `SubtitleTimeline`；播放进度解析不访问 Room、Artifact 文件或 SAF。

ASR window 与 translation batch 由固定数量的 worker 按序领取，先发布 typed Artifact，再在同一 Room transaction 中登记引用和完成状态；任务进度只按真正提交的完成单元推进，并保持单调。Partial revision 引用连续完成前缀的 WorkUnit Artifact，Final source 使用单个 `FinalTimeline` Artifact；target 保存固定 source revision/hash 的 `TranslationDelta`。翻译输出继续严格校验 cue ID，只在缺失字面量 `cue-` 前缀且补全后唯一命中预期 ID 时本地正规化，不发起额外模型请求。启动恢复只重跑没有已提交 Artifact 的单元。启动审计将缺失、损坏或未知版本引用标记为 `MissingArtifact` 或 `Storage / NeedsAttention`，不回读旧 URI，也不静默重发付费请求。不可达 Artifact 与未注册文件使用 24 小时宽限的两阶段 GC；当前 publication、target source pin 和可恢复任务资产是 GC root。

当前没有导出功能；内部 codec 与 revision reader 保留明确的 exporter 边界，但本轮不增加导出 UI。

核心 UI 接口包括 `MainTab.Playlists`、带系统角色的 `PlaylistSummary`、多对多 `PlaylistItem`、`DiscoveryGroupSummary`、来源目标偏好、`SyncTextConfig` 及对应 Repository 查询/写入。Home projection、HomeSection、物理 Folder projection、Home shortcut、瞬时 `pendingImport` 和 UI-facing Scheme/Task actions 不得成为新 UI 依赖。

## 9. 验收
