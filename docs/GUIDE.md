# VortexCue / 荧荧产品指南

> 状态：当前唯一的产品与实施指导
>
> 当前阶段：M3 退场式播放与个人内容闭环
>
> 长期背景：[`DOMAIN_CONTEXT.md`](DOMAIN_CONTEXT.md)
>
> 更新时间：2026-08-13

本文定义当前要实现和验收的产品行为。`DOMAIN_CONTEXT.md` 解释荧荧为什么存在，但不自动产生实现要求；研究报告用于提供证据和假设，也不直接覆盖本文。

荧荧是一款 Android-first、OLED-first、sleep-first 的本地内容播放器。它服务的是已经躺下、仍想继续听本地 ASMR、voice work、长视频、访谈、课程或其他长内容，却不再需要整块屏幕持续存在的人。

> **内容继续，屏幕退场；当视觉信息仍有价值时，只让当前同步文字发光。**

字幕不是播放硬门槛，但也不是媒体旁边的可选装饰。它是界面退场后仍值得保留的最小视觉内容，尤其服务跨语言理解、没有听清和需要当前语境的时刻。

## M3 目标

M3 证明的不是一个只能打开单文件的工具，而是一条从首次价值进入长期使用的完整产品闭环：

> **今晚可以直接打开，明晚可以从这里继续；值得再听的内容不必重新回到 Android 文件系统寻找。**

首次或临时使用路径是：

```text
首次样片或 Home
        ↓
打开一个内容
        ↓
发现或选择可用同步文字
        ↓
字幕中心 Normal Player
        ↓
界面逐渐退场
        ↓
Glow / 纯黑
        ↓
Sleep Timer / 退出
        ↓
进入最近并保存可恢复会话
        ↓
按用户决定加入“我的内容”
```

重复使用路径是：

```text
Home
  ↓
继续上次 / 今晚 / 我的内容
  ↓
Normal Player → Glow
  ↓
下一次从同一内容、位置、队列和表面继续
```

### M3 完成条件

- 用户不需要扫描整台设备或建立资源库，就能打开一个本地媒体并开始播放；
- 打开过一次的内容可以进入最近和 Continue，但不会因此自动等同于“已收录”；
- 用户可以把跨文件夹、跨来源的内容明确加入“我的内容”，冷启动时无需重扫即可找到；
- 用户只需选择一次常用文件夹，之后可以在荧荧内看到其已缓存的发现结果并按需刷新；
- 文件夹或设备扫描结果可以立即播放，收录和忽略不是播放前置步骤；
- 用户可以从不同来源挑选多个内容形成“今晚”，并恢复其顺序和当前项；
- 有可用同步文字时，用户能确认当前文字轨、进入字幕中心播放器并进入 Glow；
- 没有同步文字时仍能正常播放和进入退场状态，但产品不把纯黑播放当作主要差异化表达；
- 用户退出后，媒体、位置、文字轨、偏移、显示选择和最后表面可以恢复；
- 上次退出于 Glow 时，Home 通过一次明确操作直接继续 Glow，不必先经过 Normal Player；
- 单文件和明确授权的文件夹不经过“必须整理完才能播放”的流程；
- 全设备扫描只存在于“更多来源”，不在冷启动前台自动执行，也不阻塞 Home；
- 后台播放、通知、锁屏、耳机、蓝牙和 Sleep Timer 保持可靠；
- 至少完成一次创作者连续七晚真实内容使用，区分一次惊艳与重复习惯。

### M3 非目标

以下能力在获得新行为证据前不扩展：

- ASR、自动翻译和 TransVortex 消费端接入；
- 在线字幕搜索、在线内容目录、推荐和社交；
- Artist、Album、封面、EQ 和完整音乐资料库；
- 自动移动、重命名、复制或删除用户文件；
- 常驻后台全盘索引和无需用户意图的自动扫描；
- 收藏、标签、复杂合集、命名 Playlist 和完整音乐资料库管理；
- Shuffle 和通用播放器功能补齐；
- 视频观看 Surface；
- 完整 transcript 阅读器、字幕编辑器和逐词动画；
- 账号、云同步和商业订阅体系。

M3 会建立最小但真实的“我的内容”和“今晚”。现有 Queue、Playlist、Library 和扫描代码不删除，但必须逐步迁移到清晰的 Source、Collection 和 Session 边界；已有实现不自动决定最终产品结构。

## 产品原则

- **首次价值不等待整理**：先让用户播放今晚这一份内容，再决定是否长期收录。
- **个人内容集是长期价值**：Android 文件系统负责文件在哪里；荧荧负责哪些内容值得再次夜听。
- **Folder 不等于我的内容，我的内容不等于今晚**：来源、长期选择和当前消费顺序分别建模。
- **只管理引用和关系**：荧荧保存授权、索引、字幕关系、播放状态和用户决定，不移动、重命名或删除原文件。
- **消费方式优先于格式**：音频和视频都可以是主要通过声音消费的长内容。
- **界面允许退出**：越接近睡眠，产品要求用户观看和操作的内容越少。
- **同步文字是正在发生的内容**：优先显示当前 cue，不默认完整 transcript 更高级。
- **字幕优先但不强制**：有字幕时充分发挥它的价值，没有字幕时播放仍然成立。
- **用户选择优先于算法**：手动选择过的文字轨永久压过自动规则，直到用户主动恢复自动选择。
- **本地与最小授权**：文件留在原位置；单文件、文件夹和系统媒体权限按真实任务逐步请求。
- **发现不等于收录**：能够扫描不代表用户希望收录；收录也不应成为播放门槛。
- **播放器能力必须有场景理由**：Continue、快退、Sleep Timer 和媒体控制因睡前任务保留，不因“播放器通常都有”而扩张。
- **低发光而非护眼承诺**：使用“低发光”“减少发光面积”“低环境干扰”，不使用“护眼”“零伤害”或“保证睡眠”。
- **系统低打扰由应用自身边界实现**：不申请或修改全局 DND；通过界面退场和必要的系统媒体控制降低打扰。

## 三层产品模型与核心对象

荧荧明确区分三层长期职责：

```text
Source / 来源
文件在哪里，应用拥有什么访问权限
        ↓
Collection / 我的内容
哪些内容是用户明确留下、希望再次找到的
        ↓
Current Playback Session / 今晚
当前这一次按什么顺序消费，以及进行到哪里
```

三层之间不是替代关系：

> **Folder != My Content != Tonight**

这几个对象是一条联动链，不是四个需要分别经营的同级页面：

```text
添加内容 / 已授权来源
        ↓
明确保存到“我的内容”
        ↓
载入或追加到当前“今晚”
        ↓
Player 执行并持久化同一份当前 Queue
```

- Home 是应用启动后的首屏启动台，负责继续上次、开始或继续今晚，并提供少量“我的内容”和添加内容入口；
- “我的内容”是用户明确留下、以后希望在应用内再次找到的收藏/已保存列表。M3 先提供平面列表和搜索，不扩展成用户自建专辑、标签或复杂 Playlist 系统；
- “来源”是应用访问内容的范围和权限边界，不是全局资源库。用户可添加单文件、常用文件夹或低频设备媒体来源，之后从已授权来源再次进入时不必每晚重新打开文件夹；来源中的发现不会自动变成“我的内容”；
- “今晚”是当前播放 Session / Queue 的产品表达，用户对“今晚”的添加、移除和重排就是对当前 Queue 的操作；它不与另一份未来计划并列，也不要求另设一个与 Home、我的内容并列的 Queue 页面；
- 单文件打开只进入最近并可以在唯一当前 Queue 中立即播放，不自动加入“我的内容”，也不建立另一份临时 Session；“今晚”就是这份当前 Queue 的产品表达，不需要额外加入动作。

- Source 可以是单文件、SAF Folder、MediaStore 或未来的 Share / Open With；
- 一个 Source 中可以同时存在已收录、未收录和已忽略内容；
- “我的内容”可以跨越多个物理来源；
- “今晚”可以临时组合多个已收录或尚未收录的内容；
- 移除 Source、移出“我的内容”或清空“今晚”都不删除原文件。

M3 的核心领域对象是：

```text
ContentSource
├─ uri / type / displayName
├─ persistedPermission
├─ scanState / lastIndexedAt
└─ accessState

PlayableContentUnit
├─ stableId
├─ mediaLocators[1..N]
│  ├─ uri / sourceId
│  └─ accessState
├─ activeMediaLocator
├─ timedTextTracks[0..N]
│  ├─ embedded
│  ├─ sidecar
│  ├─ lyrics
│  └─ generated        future
├─ activeText
│  ├─ primary
│  └─ secondary?       optional
└─ textState
   ├─ offset
   ├─ manualSelection
   └─ rejectedCandidates

CollectionEntry
├─ contentId
├─ collectedAt
└─ availability

RecentEntry
├─ contentId
├─ lastOpenedAt
├─ position / duration / speed
└─ lastSurface

CurrentPlaybackSession
├─ queueContentIds[]
├─ currentIndex / position
├─ repeat / shuffle / speed
└─ lastSurface / sleep state
```

`PlayableContentUnit` 表达用户正在消费的内容，URI 只表达应用当前如何定位它。同一物理内容可以因单文件打开、SAF Folder 或重新定位拥有多个 locator；内容的稳定 ID 一旦建立，不得仅因当前 URI 改变而重建。

只有强等价证据才能自动把新 locator 并入已有内容，例如完全相同的持久 URI、文档提供者暴露的稳定文档身份，或用户明确执行的重新定位。不得仅因文件名、stem、大小或时长相同而静默合并；无法确认时保留独立内容，并在真正需要修复时请用户确认。

文字轨、手动选择、拒绝决定和 offset 属于 `PlayableContentUnit`，不属于某个 Source、导入草稿或一次 Active Session。草稿可以为配置变化临时保留待选文件，Session 可以保留已加载的运行时状态，但它们不得与内容目录竞争“这个内容拥有哪些文字轨”的持久事实。

同一个 `PlayableContentUnit` 可以同时出现在最近、我的内容和当前播放 Session；这些关系不复制媒体文件。打开一次产生 `RecentEntry` 和可恢复的当前 Queue，只有明确收录才产生 `CollectionEntry`。

用户界面不出现 `PlayableContentUnit`、`CollectionEntry`、`Session` 或匹配置信度等内部术语。用户只看到：

- 最近；
- 我的内容；
- 今晚；
- 字幕；
- 来源；
- 睡眠定时。

首个正式 release 之前，应用持久化只支持当前 schema。开发版或不稳定内测版的旧 schema 不形成用户数据兼容承诺；版本不匹配时可以破坏性重置应用拥有的目录、会话、设置和缓存，但不得删除或修改用户原始媒体文件。此阶段保留 schema version 用于识别并重置不兼容状态，不维护跨开发版本迁移链、旧模型 fallback 或新旧结构双写。首个正式 release 冻结数据契约时，再从当时的当前 schema 开始承担向后兼容责任。

## 应用结构

```text
首次体验
├─ 体验短样片
├─ 打开自己的内容
└─ 添加常用文件夹

Home / 今晚的启动台
├─ NOW
│  ├─ 继续上次
│  └─ 今晚队列
├─ MINE
│  └─ 我的内容窗口
└─ MORE
   ├─ 新发现
   └─ 添加内容或来源

我的内容
├─ 最近
├─ 已收录
├─ 搜索
└─ 来源入口

来源与发现
├─ 已授权文件夹
├─ 可选设备媒体扫描
├─ 新发现 / 已忽略
└─ 刷新与权限状态

Normal Player
├─ 当前字幕语境
├─ 基础播放控制
├─ 字幕轨与同步
├─ 今晚、Queue 与 Sleep Timer
└─ 进入 Glow

Glow
├─ 当前同步文字
├─ 字幕间隙 / 无字幕纯黑
├─ 沉浸锁定
└─ 临时操作
```

上面的结构表达职责，不要求四个对象都成为同级导航项：

- “来源”作为“添加内容 / 文件夹与权限 / 新发现”的访问与管理区域，从 Home 或“我的内容”进入；它不要求用户先理解 `Source` 这个内部术语；
- “今晚”从 Home、播放器或“我的内容”进入编辑，承担当前播放顺序，不必单独占一个顶级页面；
- `Queue` 在 Home 与 Normal Player 中是同一个当前 Session 的两种表面，不另建平行模型或第二份 Queue。

Home 不是完整资源库浏览器，“我的内容”也不是隐藏在高级管理页里的底层能力。M3 可以先用一个页面承载这些区域，不提前锁定底部导航；信息层级必须稳定为 `NOW → MINE → MORE`。

## 首次体验

首次启动不先请求全设备媒体权限，也不要求建立资源库。

主路径使用一份可合法随应用分发、长度约一分钟的样片，直接证明：

```text
声音和时间继续
        ↓
完整播放器退场
        ↓
只剩当前同步文字
        ↓
字幕间隙回到纯黑
```

微光亮度校准嵌入第一次样片 Glow，不建立独立的多步骤设置向导。目标是“清晰、舒适、不费力”，不是越暗越好。

用户可以跳过样片并直接打开自己的内容。首次样片、亮度校准和打开文件都不得依赖全盘媒体权限。

## Home、继续与今晚

Home 是“今晚的启动台”，按顺序回答三个问题：

1. 我上次进行到哪里、今晚是否已有安排；
2. 我长期留下了哪些值得再听的内容；
3. 新内容从哪里进入。

### Active Session

首页最强位置只保留一个动态 Active Session 区域：

- 单个内容未完成时显示“继续上次”；
- 当前 Queue 已有内容时显示“今晚继续”、当前项和接下来的内容；尚未播放只表示当前位置为起点，不产生独立 Draft；
- 没有会话时不显示空卡片，由打开内容和添加来源承担首次动作。

继续区域至少显示：

- 内容标题与 Tonight 中的位置；
- 上次播放位置；
- 当前字幕语言或“无字幕”；
- 上次表面是 Normal 还是 Glow；
- 当前文件不可用时的明确恢复状态。

应用冷启动本身不自动播放。用户点击“继续”是明确播放动作：

- 点击“继续”同时完成恢复并开始播放，不要求进入播放器后再次点击播放；
- 上次表面为 Glow 且媒体、文字关系仍有效时，直接恢复 Glow；
- 上次表面为 Normal 时，恢复 Normal；
- 媒体或字幕不可读时进入可解释的修复流程，不静默丢失字幕；
- 不要求用户先重新进入来源、重新扫描或重新收录内容。

### 我的内容窗口

Home 只展示“我的内容”的小型窗口，例如数量、最近使用和少量条目；完整浏览、搜索和收录管理进入“我的内容”。它不是首页的全部，也不能被降级成只有进入管理页才能找到的隐藏能力。

### Progressive Home

Home 随用户状态逐渐生长：

```text
首次：样片 / 打开内容 / 添加文件夹
已有内容：继续 / 我的内容 / 添加
已有 Tonight：今晚继续 / 接下来 / 我的内容
```

首次空状态保留“打开一个内容”和“添加常用文件夹”的明确文字入口。“扫描设备媒体”不得成为第一 CTA。用户已经形成稳定内容集后，可以把低频添加动作收进统一入口，但不在 M3 提前锁定具体按钮形式。

## 内容进入路径

### 打开一个内容

单文件是最快的高意图路径：

```text
选择一个媒体
   ↓
解析或建立内容单元
   ↓
恢复已记忆的文字关系
   ↓
发现内嵌文字轨
   ↓
使用已选外挂字幕，或按需手动选择
   ↓
Normal Player
```

- 音频和视频均可打开；视频只提供音轨、时间和文字轨，不创建观看 Surface；
- “打开内容”的主动作只选择一个音视频文件；字幕选择是内容建立后的可选次级动作，不把两次系统文件选择表现为必须组装的两个并列条件；
- 现有界面先选媒体、再选字幕的两个系统选择器只是早期导入草稿的过渡输入，不代表两个 Source，也不代表媒体和字幕需要长期维护两条并列路径；兼容该入口期间，媒体确认后仍应先建立内容，随后选择的字幕直接绑定到该内容；
- 单文件打开后直接形成可恢复内容并进入最近，不进入待整理，也不自动加入“我的内容”；
- 从单文件、来源或“我的内容”打开 / 立即播放一个内容时，用该内容替换当前 Queue；它自然形成单项播放 Session，不创建临时 Playlist 或播放完自动移除的特殊条目；
- “加入今晚”只追加而不切换播放；用户明确播放一个 Playlist、Folder 顺序或多选结果时，用该顺序替换当前 Queue。界面必须让“立即播放”“加入今晚”和“播放这一组”的结果可预期；
- 播放前后都可以明确执行“加入我的内容”，该动作只保存应用内引用和关系；
- 没有字幕不阻止播放；
- 当媒体已经确定时，用户手动选择的字幕立即写入该内容的文字轨关系，关闭对话、返回 Home 或尚未开始播放都不得丢失；
- 更换媒体时不继承上一个媒体的待选字幕，而是恢复新内容自己的文字轨关系；
- 同一内容从单文件、已授权 Folder 或明确重新定位进入时，只要存在强等价证据，就恢复同一内容单元及其文字关系；
- 单文件授权不能可靠枚举相邻文件，需要自动发现外挂字幕时再邀请用户选择包含内容的文件夹；
- 用户以后可以在播放现场查看、更换、移除或恢复自动字幕选择。

### 打开一个文件夹

明确授权的小文件夹是来源边界，也是系列内容和外挂字幕的自然发现范围：

```text
选择文件夹
   ↓
扫描这个授权范围
   ↓
发现媒体和文字轨
   ↓
建立高置信关系
   ├─ 立即播放
   ├─ 收录到我的内容
   └─ 忽略
```

- 扫描结果立即可以播放，不要求先完成整理或收录；
- 添加 Folder 后保存 SAF 授权和可重建索引，用户不应每晚重新经过系统文件选择器；
- Folder 是 Source，不自动等同“我的内容”，其内部可以同时有已收录、未收录和已忽略内容；
- 已缓存索引必须能在冷启动时显示；刷新由用户明确触发或在进入来源时非阻塞执行；
- 收录支持逐项和批量操作，但不得把整个文件夹默认视为用户认可的消费集合；
- 同目录完全同主文件名可以高置信关联；
- Folder 发现的媒体若与已有单文件内容具有强等价身份，应为已有内容增加 locator 并保留手动字幕决定，不创建一份丢失关系的重复内容；
- `.zh`、`.en`、`.ja`、`.forced`、`.sdh`、`.cc` 等后缀作为语言或角色信息保留；
- 多个候选全部保留，不选择“最短文件名”后丢弃其他轨；
- 不明确的候选只建议，不自动激活；
- 深层或大型目录必须避免阻塞 Home，并提供可见的扫描状态和取消能力。

### 来源、发现与我的内容

“我的内容”保存用户明确认可的跨来源内容；来源页负责文件夹、MediaStore 和访问状态；“新发现”负责尚未决定的索引结果。三者不能继续混成一个资源库管理页。

全设备 MediaStore 扫描继续作为低频可选来源，不能代表“我的内容”，也不能因为平台允许访问就自动运行。

只有广泛扫描继续使用：

```text
扫描发现
→ 立即可播放的新发现
→ 按用户决定收录或忽略
```

M3 不在冷启动时自动执行全设备扫描，也不递归重新检查全部授权文件夹后才显示 Home。冷启动恢复持久目录、来源快照和当前会话，并按需验证当前需要访问的 URI；重扫由用户明确触发，或在进入对应来源时以不阻塞主路径的方式执行。

新发现保持安静：它可以在 Home 显示数量和来源，但不使用警告语气，也不阻塞 Continue、Tonight 或播放。用户不处理 Inbox 时，已收录内容仍然稳定可用。

广泛扫描仍遵守：

- 发现不等于收录；
- 打开和播放也不等于收录；
- 视频默认不选；
- 已忽略内容不反复打扰；
- 移出“我的内容”、忽略条目、移除来源和清空 Tonight 都不删除原文件；
- 应用不提供移动、重命名和整理磁盘目录的文件管理操作；
- 收录条目的媒体快照、文字关系和用户决定必须持久化，不能依赖下次扫描重建后才出现；
- 部分媒体权限范围必须清楚可见；
- MediaStore 字幕索引只能作为补充发现来源，不作为全部文字关系的真相。

## 同步文字发现与选择

字幕发现和字幕激活是两个不同决定：

```text
发现文字轨
    ↓
判断它是否属于当前媒体
    ↓
建立候选关系
    ↓
判断用户现在要看哪一轨
    ↓
激活 primary / secondary
```

首次进入内容时，文字轨发现按以下顺序尝试：

1. 读取容器内嵌文字轨；
2. 恢复该内容已经持久化的文字轨关系和用户选择；
3. 在当前已授权的 Folder Source 范围内发现外挂候选；
4. 没有高置信候选时，才邀请用户手动选择。

这是发现和准备的回退顺序；用户已经明确确认过的文字轨仍拥有最高激活优先级，不得被内嵌轨或新候选静默覆盖。

优先级如下：

| 来源 | 自动建立关系 | 自动激活 |
| --- | --- | --- |
| 用户此前手动选择 | 是 | 是，最高优先级 |
| 容器内嵌文字轨 | 是 | 明确 default 或符合已知语言偏好时 |
| 同目录完全同 stem 外挂字幕 | 是 | 唯一候选且无手动选择时 |
| 带语言/角色后缀的同名字幕 | 全部保留 | 有明确语言偏好时，否则询问 |
| 可解释的剧集或版本候选 | 只建议 | 否 |
| 模糊文件名或跨目录候选 | M3 默认不出现 | 否 |

每条文字轨至少能够表达：

- 来源：内嵌、外挂、歌词或未来生成；
- 格式和 URI；
- 语言、名称和角色；
- 是否 default、forced、SDH/CC；
- 匹配依据；
- 是否由用户手动选择；
- 是否曾被用户拒绝；
- 当前是否可读和可解析。

手动选择的文字文件一旦由用户确认，就成为当前 `PlayableContentUnit` 的持久文字轨；读取和解析结果只更新它的可读状态和修复信息。“应用并播放”只决定何时进入 Player，不得成为字幕关系是否保存的额外提交步骤。手动选择必须原子地更新文字轨目录和当前选择，并可在进程重建后恢复。

M3 保留现有 SRT、LRC、WebVTT、ASS 和 SSA 外挂字幕解析。内嵌文本字幕应接入同一时间轴；图形字幕不应伪装成可用于 Glow 的文本轨。

自动关系读取或解析失败必须显示可恢复状态，并允许重新选择。已有字幕时，Normal Player 仍必须提供查看、切换、更换和移除入口。

## Normal Player

Normal Player 是用户确认内容、理解当前语境和进入退场状态的地方，不复制传统音乐播放器的封面中心布局。

字幕区域按以下层级组织：

```text
上一句          弱
当前句          主视觉
下一句          弱
```

M3 目标能力：

- 当前 cue 与播放时间严格联动；
- 上一句、当前句和下一句提供必要上下文；
- 支持重听当前句或点句跳转；
- primary / secondary 可以独立选择和显示；
- 主次语言拥有独立但克制的视觉层级；
- 字幕 offset 可以调整和重置；
- 当前已有字幕时也能直接管理文字轨；
- 字幕缺失或失败时给出明确的添加或修复动作；
- 进入 Glow 是有同步文字时的主要退场动作。

完整可滚动 transcript、全文搜索和逐词高亮不是 M3 完成条件。它们只有在真实长内容使用证明上下文浏览不足时再进入范围。

普通播放器仍保留：

- 标题与必要元数据；
- 可拖动进度；
- 播放或暂停、快退、快进和上下项；
- 倍速；
- Queue；
- Sleep Timer；
- 返回 Home。

视频容器只播放音轨并驱动文字时间轴。产品不提供视频观看界面。

## Glow

Glow 不是普通播放器隐藏控件后的皮肤，而是退场体验的沉浸表面：

- 有同步文字时只显示纯黑背景和当前 cue；
- primary / secondary 按用户选择显示，不强制双语；
- 字幕间隙不填充装饰、封面、频谱或提示；
- 没有同步文字时纯黑仍是合法退场状态；
- 无字幕 Glow 可以保留控制能力，但不取代“只让字幕发光”成为主要产品表达；
- 默认处于沉浸锁定，普通单次触碰不弹出完整操作栏；
- 左、中、右区域双击分别执行快退、播放或暂停、快进；
- 长按进入临时操作，数秒无操作后重新锁定；
- 临时操作只保留进度、基础控制、Sleep Timer、字幕偏移、文字轨和返回 Normal；
- 退出时保存当前表面，下一次可以直接继续 Glow。

Glow 锁定只防止应用内误触，不冒充系统锁屏或 AOD，也不拦截来电、闹钟和系统安全行为。

窗口亮度、字幕像素亮度和临时控制亮度保持独立。普通界面保持清晰可读，低亮度只属于 Glow。

### 手机方向

- 手机是当前主目标，Normal 和 Glow 默认使用竖屏；
- 不跟随重力传感器自动旋转；
- 横屏只能由应用内的明确操作进入，不能由系统传感器强行改变当前表面；
- 大屏只保证基本启动、播放和退出，不为其单独设计前台播放或横屏信息架构。

当前 `compileSdk` / `targetSdk` 为 37，表示面向 Android API 37（Android 17）的构建与兼容目标，不表示用户设备必须运行“版本 37”。在手机尺寸上，应用仍可按上述规则控制方向；在 `smallest width >= 600dp` 的大屏上，Android 17 会忽略 `screenOrientation` 和 `setRequestedOrientation()` 等方向限制，因此大屏不承诺锁定方向。参见 [Android 17 方向与可调整大小变更](https://developer.android.com/blog/posts/prepare-your-app-for-the-resizability-and-orientation-changes-in-android-17) 和 [应用方向指南](https://developer.android.com/develop/adaptive-apps/guides/app-orientation-aspect-ratio-resizability)。

## 播放、今晚与 Sleep Timer

`PlaybackService` 内的 Player / MediaSession 是播放状态唯一真相。离开界面、关闭屏幕或应用进程重建时，应用层不建立第二套播放事实。

Continue 至少保存：

- 当前媒体；
- 播放位置和已知时长；
- 倍速；
- Queue 与当前项；
- Repeat / Shuffle 的现有状态；
- active primary / secondary；
- 字幕 offset；
- 最后 Normal / Glow 表面；
- Glow 显示配置；
- URI 可用性和修复信息。

Sleep Timer 至少支持：

- 常用分钟数；
- 当前内容结束后停止；
- Tonight 队列结束后停止；
- 剩余时间；
- 取消；
- 在 Normal 和 Glow 中均可低摩擦进入。

“今晚”是当前持久化播放 Session / Queue 的产品表达。用户可以在播放前后跨来源追加、移除或重排内容；这些操作直接作用于当前 Queue，不维护一份等待开始且与播放器队列并列的未来 Draft。

`PlaybackService` 中的 Queue 是唯一实时播放真相；持久层只保存其恢复快照，不作为第二份可编辑状态参与双向同步。Playlist、Folder 或用户多选可以复制为当前 Queue 的初始顺序，当前 Queue 的后续修改不反向改变来源。

所有内容入口只操作这一个 Queue：打开或立即播放单个内容执行 `replace`，加入今晚执行 `append`，明确播放 Playlist、Folder 顺序或多选结果也执行 `replace`。这些是同一 Queue 的不同操作，不是不同类型的播放会话。若未来出现“先听这个再继续原队列”的真实需求，应提供明确的“接下来播放”操作，而不是改变普通“播放”的语义。

M3 的 Tonight 规则是：

- 可以从我的内容、新发现或单次打开内容中加入；
- 支持查看顺序、移除和重排，不要求创建或命名 Playlist；
- 第二天恢复同一当前 Queue、当前项和位置；
- 播放到队尾不会因为 Repeat 或一次自然结束而隐式清空 Queue；只有用户清空或用其他内容替换时结束当前编排；
- 当前项切换时使用该内容自己的文字轨和 offset；播放进度不属于 Playlist 或 Queue 条目，Session 只持久化当前项和当前项位置；
- 单内容播放仍是合法的退化情况，不强迫用户先建立 Tonight。

Folder 的自然顺序、现有 Playlist 或用户明确选择的多个内容都可以为当前 Queue 提供初始顺序。复杂命名播放列表不是 M3 目标；未来若需要长期复用当前组合，应显式“保存为 Playlist”，而不是保留另一份 Tonight Draft。

## 视觉语言

- 全局使用 OLED 纯黑背景，层级主要依靠排版、间距、透明度和细分隔；
- 不使用大块强调色、彩色卡片、渐变背景和装饰性发光；
- 品牌黄色只用于当前选择、进度、焦点和少数关键动作；
- Logo 只出现在启动、关于或真正需要品牌识别的时刻；
- 主界面不反复解释产品功能或展示操作说明；
- 页面与系统栏尽量融合，减少套用系统模板的感觉；
- 动效以淡入、淡出和克制的位置变化为主；
- 普通界面保持清晰和足够触控面积，低亮度只属于 Glow；
- 每个常驻元素都必须帮助用户开始、理解、控制或继续当前内容。

## 工程边界

工程继续保持单一 `app` 模块，不为目录整齐提前拆分 Gradle 模块。Kotlin 包按职责组织：

```text
app       Activity、应用组合根与系统入口
core      内容体验单元、共享模型与存储格式
library   Source、发现索引、我的内容、Folder 与持久化
playback  MediaSessionService、Current Playback Session / Queue 与 Sleep Timer
subtitle  文字轨发现、读取、解析、时间轴与缓存
ui        首次体验、Home、Player 和主题
```

- `PlaybackService` 内的 Player / MediaSession 是播放状态唯一真相；
- `PlayableContentUnit` 是媒体 locator、文字轨及用户选择的持久唯一真相；导入草稿只保留尚未确认的交互状态，Active Session 只保留已加载的运行时状态，两者都不重复持久化字幕事实；
- 后台播放服务只接受本应用和系统认可的可信控制器，应用私有命令不向外部控制器开放；
- `app` 连接系统入口和功能状态，不重新实现来源、字幕或播放规则；
- Home 不直接拥有扫描和内容关系算法；
- “我的内容”只操作应用内目录和用户关系，不直接执行文件系统删除、移动或重命名；
- 扫描、匹配、轨道排序、schema 判定和恢复规则保持为可测试的纯逻辑；
- 首个正式 release 前只读取当前 schema；不兼容的开发数据直接重置，不为内部测试数据累积迁移代码；
- 媒体文件不复制到应用目录；授权、来源快照、内容目录、用户关系和小型文字缓存可以持久化；
- 只有出现真实构建、隔离或复用需求时才增加 Gradle 模块。

## M3 实施顺序

### M3.0 规格与基线

1. 以本文替换“资源库优先”和“资源库仅是底层支撑”两个不完整极端；
2. 还原并记录一次产生强烈正向体验的 Golden Session；
3. Golden Session 至少记录近似版本、内容类型、文字轨、单双语、亮度、设备、距离、环境光和退出后的感受；
4. 真机验证开始时建立 M3 记录，不把计划预先写成“已验证”；设备前置检查、厂商差异和证据规则遵循 [`records/ANDROID_DEVICE_VALIDATION.md`](records/ANDROID_DEVICE_VALIDATION.md)。

### M3.1 恢复核心路径

1. 保存并恢复 `lastSurface`；
2. Home 将继续、打开内容和更多来源按意图重新排序；
3. 上次处于 Glow 时，一次操作直接继续 Glow；
4. 单文件不经过资源库整理即可播放和恢复；
5. 冷启动不执行阻塞式全设备扫描；
6. 先复用现有外挂字幕、Normal Player、Glow、MediaSession 和 Sleep Timer；
7. 不在这一阶段删除 Library、Queue 或 Playlist。

状态：已完成代码与 Android 16 真机验证。M3.1 是后续结构的基础，不因个人内容方向纠偏而回滚。

### M3.2 建立内容目录与文字关系

1. 引入 `PlayableContentUnit` 和稳定内容 ID；
2. 将 Source、Recent、Collection 和 Active Session 的持久状态分离；
3. 单文件打开只写入 Recent，不再自动写入 Collection；
4. 持久化已收录内容的媒体快照、来源、可用性和用户决定，冷启动不依赖重扫；
5. 从单一字幕附件演进为 `0..N` 文字轨，保存语言、角色、来源、匹配依据和手动选择；
6. 恢复 primary / secondary 显示，并接入内嵌文本字幕；
7. 让解析失败和 URI 失效可见、可重新定位；
8. 内容目录与会话各自使用明确的当前 schema，版本不匹配时按预发布策略重置；
9. 为目录分层、轨道排序、手动优先、schema 判定和恢复增加单元测试。

#### M3.2a 第一实现切片

本切片只建立“可以安全继续演进的目录事实”，不同时重做 Home、Folder、Tonight 和全部字幕 UI：

1. 增加版本化的内容目录快照，保存已知 `MediaSourceRef`、来源和收录决定；
2. 将 Recent 与 Collection 分开持久化，新打开内容只进入 Recent；
3. 已收录内容在无扫描冷启动中恢复，扫描只负责发现变化和验证来源；
4. Playlist 中的内容继续按已收录关系参与目录，不与 Recent 混用；
5. `includedUris` 暂时缺少媒体快照时继续保留，待对应当前来源可读时补全；
6. 先提供领域层的收录 / 移出能力和当前 schema 测试，再接入最小用户动作；
7. 不在该切片引入 Room、收藏、标签、命名 Playlist、后台常驻扫描或新导航结构。

这个切片完成后，代码中不再使用“单独打开列表”同时表达最近、收录和来源三个概念。

状态：目录分层代码、自动化检查和 Android 13 真机流程已完成。早期 v3→v4 原位升级结果仅作为历史工程记录保留，不构成当前兼容要求；version 6 已删除该迁移路径。详见 [`records/M3_CATALOG_VALIDATION.md`](records/M3_CATALOG_VALIDATION.md)。

#### M3.2b 第二实现切片

本切片在 M3.2a 的内容目录之上建立稳定内容单元和多文字轨事实，仍不同时改造 Home、Tonight 或播放界面：

1. 为每个已知媒体快照建立确定性的稳定内容 ID，并以 version 5 持久化 `PlayableContentUnit`；
2. 每个内容单元可以保存 `0..N` 文字轨，以及来源、定位信息、格式、语言、名称、角色、匹配依据、可读状态和 primary / secondary 选择；
3. Folder 匹配保留全部 exact、语言和角色后缀候选，不再只留下最短文件名；唯一 exact 候选才自动成为 primary，多个不明确候选只建立关系；
4. 用户手动选择或明确移除 primary 后，后续自动候选不得覆盖；被拒绝候选即使暂时消失，也保留拒绝决定；
5. 用户手动选择的外挂字幕直接形成稳定的 `UserSelected` 轨和手动 primary，不额外维护 URI 字幕关联表；
6. 该切片先建立目录事实；内嵌轨播放、secondary 显示、失效修复和完整轨道选择 UI 由后续切片接入。

状态：稳定内容单元与文字轨目录代码已完成。早期 v4→v5 原位升级和旧关联保留结果仅作为历史工程记录保留；version 6 已删除 `SubtitleAssociation`、Legacy 轨和对应迁移路径。详见 [`records/M3_CONTENT_UNIT_VALIDATION.md`](records/M3_CONTENT_UNIT_VALIDATION.md)。

#### M3.2c 第三实现切片

本切片让 M3.2b 的文字轨目录进入真实播放和恢复路径：

1. 从 Media3 运行时发现可用于 Glow 的内嵌文本轨，保存语言、名称、default / forced / SDH / CC 角色和设备可用状态；
2. Normal Player 与 Glow 按当前选择显示 primary / secondary，并提供轨道查看、手动切换、关闭、添加文件和恢复自动选择；
3. 同一时间只启用一条内嵌文本轨；它可以和一条应用时间轴驱动的外挂字幕组成主次轨，不能把两条内嵌轨误报为同时可用；
4. 新打开媒体且没有手动选择外挂字幕时保留自动规则，不把“未选择文件”写成手动关闭 primary；
5. 冷启动恢复媒体、位置、内嵌主轨、外挂副轨、offset 和最后表面，不依赖重新扫描；
6. 当前媒体 URI 失效时显示可恢复状态；重新定位到等价媒体后重建内嵌轨，并保留内容关系、外挂轨和主次选择；

#### M3.2d 第四实现切片

本切片收口早期“分别选择媒体与字幕，再应用为一次会话”的过渡实现，让 M3.2b 已建立的内容与文字轨目录成为所有进入路径的持久事实：

1. 单文件打开先解析或建立 `PlayableContentUnit`，再恢复已有文字轨；不要求用户为一次普通打开并列组装媒体和字幕两个文件；
2. 当前内容已确定时，手动选择、更换或移除字幕立即更新该内容的文字轨和选择；关闭导入界面、返回 Home、重新打开或进程重建后均不丢失；
3. 更换媒体时清理仅属于旧媒体的导入草稿，并恢复新内容自己的字幕关系，不得把上一内容的字幕误绑到新媒体；
4. 将内容稳定 ID 与当前 URI locator 分离；等价 SAF 文档身份或用户明确重新定位可以为已有内容增加 locator，文件名、大小和时长等弱信号不能独立触发静默合并；
5. 单文件与 Folder Source 若解析为同一内容，必须复用同一文字轨目录、手动选择、拒绝决定和 offset；
6. 刷新或移除 Source 只更新 locator 和访问状态；只要内容仍被 Recent、Collection 或 Active Session 引用，就保留内容 ID、手动文字轨和用户决定，并在需要时显示失效或重新定位状态；
7. 导入草稿和 Last Session 不持久化字幕引用；启动恢复只从内容目录读取文字轨与选择，不设置旧模型 fallback；
8. 持久更新必须按用户操作顺序串行化，并覆盖用户在写入后立即返回或进程被重建的情况，不依赖未跟踪的 fire-and-forget 保存。

本切片不删除已实现的 secondary 轨，不引入媒体全文哈希、文件移动或完整的 Home / Source 信息架构重做。“我的内容”列表、Folder Source 表面和新发现 Inbox 仍属于 M3.3。

状态：代码实现、自动化检查与 Android 13 真机验收完成。单文件导入现在会在媒体确认后建立内容，导入草稿可分别选择、移除和并行读取可选 primary / secondary 外挂字幕；每次手动选择先完成内容目录写入再更新草稿状态，同一字幕文件不会同时占用两个显示槽。更换媒体按新内容恢复，启动只从内容目录恢复字幕，目录写入按操作顺序串行化。Library version 7 将 `PlayableContentUnit` 改为稳定内容 ID、`1..N` 个媒体 locator 与 active locator；SAF authority + document ID 作为强等价身份，单文件 URI 与 Tree URI 可以复用文字轨、选择和 offset，文件名、大小与时长不参与静默合并。明确重新定位只增加 locator，不再更换内容或文字轨 ID；Folder 刷新与移除只更新 locator 可用性，仍被 Recent、Collection、Playlist 或当前会话引用的内容事实继续保留。Session version 2 不再单独持久化 offset。详见 [`records/M3_IMPORT_HOME_VALIDATION.md`](records/M3_IMPORT_HOME_VALIDATION.md)。

### M3.3 建立我的内容与来源

M3.3 默认 M3.2d 已经保证同一内容从单文件和 Folder Source 进入时复用同一文字关系；本阶段只建立用户如何再次找到这些内容与来源的产品表面，不重新定义绑定语义。

1. 提供最小“我的内容”列表、搜索和收录 / 移出操作；
2. 明确授权的小文件夹成为可长期返回的 Source，并持久化其发现快照；
3. Folder 扫描结果立即可播放，同时支持逐项或批量收录和忽略；
4. exact 和语言后缀文字候选全部保留，不明确候选只建议；
5. 新发现以安静 Inbox 呈现，不阻塞播放，也不因未处理而反复告警；
6. 可选全设备扫描继续作为低频 Source，不重新占据首次或 Home 主路径；
7. 所有移除操作明确为应用内引用操作，不删除原文件。

#### M3.3a Home 与我的内容表面

本切片先把已经存在的目录能力重排为稳定的产品入口，不修改 Library version 7：

2. 首次空状态只保留“打开一个内容”和“添加常用文件夹”，不显示空的继续卡片、内容集或设备扫描 CTA；
3. Home 的“我的内容”窗口按最近使用排序，最多展示少量已收录条目，并进入完整页面；
4. “我的内容”明确区分“已收录”和“最近”，搜索同时覆盖两者并标明关系状态；移出“我的内容”不清除最近记录，也不删除原文件；

### M3.4 建立今晚

8. 单内容打开 / 立即播放替换当前 Queue，“加入今晚”追加，明确播放一组内容时也用该组替换当前 Queue。

北极星信号仍然是：

即用户在没有研究员推动的情况下，用自己的内容第二次、第三次主动进入 Glow。

- 从 Home 到恢复播放的时间；
- 已收录内容的再次播放率；
- Folder Source 的再次访问是否避免了系统文件选择器；
- Tonight 中第二项及后续项的实际播放率。

## 验证与决策

### 自动化验证

改动相关范围至少覆盖：

- 单文件打开进入 Recent 但不自动进入 Collection；
- 收录内容和来源快照可以在不扫描的冷启动中恢复；
- 当前 Library 与 Session schema 可以冷启动恢复，版本缺失或不匹配时按预发布策略重置；
- 文字轨匹配和排序；
- 手动选择压过自动规则；
- 媒体已确定后手动选择字幕，关闭导入界面、返回 Home、重新打开和进程重建后关系仍保留；
- 导入草稿的 primary / secondary 字幕可以独立选择、取消和并行读取，同一字幕不会同时占用两个显示槽；
- 更换媒体不继承上一内容的导入字幕；
- 具有强等价身份的单文件与 Folder locator 复用同一内容 ID 和文字关系，弱信号相似的不同内容不会被静默合并；
- 明确重新定位保持内容 ID、文字轨 ID、主副选择和 offset，Source 刷新或移除只改变 locator 可用性；
- 被拒绝候选不会重新自动激活；
- 内容目录是字幕关系的唯一持久来源，Draft 与 Last Session 不含字幕副本；
- 当前 Queue 切换恢复每项自己的文字关系；
- 当前 Queue 在进程重建后保留顺序、当前项和位置；
- `lastSurface`、位置、offset 和显示状态恢复；
- 广泛扫描不会由普通冷启动触发。

### 真机验证

通用设备前置检查、厂商差异、SAF 边界、生命周期回归和夹具清理规则见 [`records/ANDROID_DEVICE_VALIDATION.md`](records/ANDROID_DEVICE_VALIDATION.md)；本轮 MIUI 观察见 [`records/MIUI_VALIDATION_NOTES.md`](records/MIUI_VALIDATION_NOTES.md)。

涉及以下行为必须使用真实 Android 设备：

- 单文件和 SAF Folder 授权；
- 安装带有不兼容开发 schema 的版本后，应用状态被重置且用户原始媒体文件不受影响；
- 单文件选择媒体后手动选择字幕，返回 Home 并重新打开后字幕仍属于该内容；
- 将同一媒体所在 Folder 加入为 Source，再从 Folder 进入时恢复既有手动字幕关系；
- 选择字幕后立即返回、强制停止并冷启动，关系和当前选择不丢失；
- 打开一次、明确收录、移出我的内容和原文件仍存在；
- 从已授权 Folder Source 再次进入时不重新经过系统文件选择器；
- 从多个来源加入 Tonight、重排、跨项播放和第二天恢复；
- 内嵌与外挂文字轨；
- 后台 MediaSession、通知、锁屏、耳机和蓝牙；
- 进程重建与 URI 失效恢复；
- Normal → Glow → Continue；
- OLED 纯黑、字幕 gap 和亮度；
- Sleep Timer 与内容结束；
- 大 Folder 扫描的取消和非阻塞表现。

### 决策分支

- **Go**：用户理解它与锁屏、视频播放器的区别，并用自己的内容重复进入 Glow；
- **Rework A**：喜欢 Glow，但大量内容没有字幕，下一步验证 ASR、TransVortex 或翻译供给；
- **Rework B**：喜欢睡前播放但很少看字幕，继续强化 sleep-first，字幕保留为差异能力；
- **Rework C**：Glow 成立但 Android 文件查找和跨来源选择仍重，优先改善 Source、我的内容和 Tonight，不扩展通用音乐库；
- **Rework D**：用户主要依赖 Recent / Continue，几乎不主动收录或建立 Tonight，收缩对应表面但保留底层关系；
- **No-Go / 重新定位**：充分体验后仍普遍选择直接锁屏，或 Glow 只产生一次新奇而没有第二次使用。

在完成 M3.5 的真实夜间使用前不开始 M4，也不以更多案头研究替代行为验证。M3.2 之后每个里程碑都必须带真实内容走通，不等待全部结构完成后再测试。
