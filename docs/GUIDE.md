# VortexCue / 荧荧当前指南

> 状态：当前唯一的产品与实施指导
>
> 当前阶段：从单会话原型升级为 OLED-first 本地播放器
>
> 更新时间：2026-08-09

本文统一说明荧荧接下来要做成什么、各产品表面承担什么职责，以及下一阶段的实施优先级。具体类结构、存储选型和小步任务由实际改动决定，不在这里提前拆出复杂架构。

验证记录、品牌探索和早期研究只提供证据与背景；当结论发生变化时直接更新本文，不再建立平行规格。

## 1. 产品定义

VortexCue / 荧荧是一款以 OLED 微光体验为核心的本地音频播放器。它先让用户能够快速找到、整理并可靠播放自己的内容，再在睡前、暗室或宿舍等环境中让手机界面逐渐退场。

> 内容层让用户迅速找到要听的东西，播放器让声音可靠继续，微光让手机从环境中消失。

同步字幕是荧荧的重要增强内容，但不是播放或进入微光的前提。没有字幕时，用户仍然可以正常播放，并进入只保留声音和必要临时控制的纯黑微光状态。

### 产品原则

- **OLED-first**：纯黑和低发光不是播放器里的一个皮肤，而是整套产品的视觉与交互基础。
- **播放器先完整**：找得到、排得好、播得稳是微光体验成立的前提。
- **本地优先**：本地扫描、用户授权的文件与文件夹无需账号或网络即可使用。
- **字幕可选**：有字幕时提供同步阅读，没有字幕时微光仍然成立。
- **界面会退场**：普通界面清楚克制，微光界面只在用户需要时出现控制。
- **保持简单**：功能围绕内容管理、播放和微光展开，不为假设中的规模预建复杂工程。

### 当前边界

当前以本地音频和视频容器中的音轨为播放内容，不显示视频画面。外部 SRT、LRC、WebVTT、ASS/SSA 字幕继续作为正式能力。

当前不进入范围：

- 在线流媒体目录、推荐和社交；
- 账号与云同步；
- ASR、翻译、字幕编辑和在线字幕搜索；
- 视频观看界面；
- 完整复刻 ASS 或 WebVTT 的原始视觉特效；
- 均衡器和复杂音效系统。

未来功能只有在明确改善“找到内容、可靠播放或进入微光”时才进入范围。

## 2. 产品结构

```text
首页 / 内容库
├─ 继续播放、最近内容、搜索与分类
├─ 本地扫描、文件夹与单文件导入
└─ 播放列表
          ↓
      普通播放器
      ├─ 当前内容与完整播放控制
      ├─ 队列、播放模式与睡眠定时
      ├─ 字幕与同步调整
      └─ 进入微光
          ↓
        微光
        ├─ 沉浸锁定
        ├─ 手势或点击区域
        └─ 临时控制

设置
├─ 微光校准
├─ 字幕外观
└─ 内容来源与数据管理
```

具体采用底部导航、顶层页面还是覆盖层，可以在 UI 原型中调整；各部分职责保持稳定。

### 2.1 首页与内容库

首页既是回到播放的入口，也是本地内容的工作层。默认优先展示：

1. 正在播放或继续上次；
2. 最近播放和最近加入；
3. 搜索；
4. 歌曲、专辑、歌手、文件夹和来源等浏览入口；
5. 用户播放列表。

首页不再承担媒体与字幕的调试式配置。播放进行中时保留一个轻量、低发光的“正在播放”入口，不使用大块彩色卡片占据屏幕。

### 2.2 普通播放器

普通播放器负责所有明确、可见的播放操作。它至少包含：

- 标题、歌手、专辑等必要信息；
- 当前时间、总时长和可拖动进度；
- 上一项、播放或暂停、下一项；
- 快退与快进；
- 队列入口；
- 随机与循环；
- 播放倍速；
- 睡眠定时；
- 字幕选择、字幕偏移和当前字幕语境；
- 进入微光。

封面可以作为辅助信息，但不应以高饱和大图或取色背景主导页面。没有封面或字幕时，页面仍应完整、稳定，而不是表现成缺少必要资源的错误状态。

### 2.3 微光

微光是独立的沉浸播放状态，不是普通播放器简单隐藏几组控件后的结果。

锁定时持续显示的内容只有：

```text
有字幕：纯黑背景 + 当前字幕
无字幕：纯黑背景
```

进度、标题、控制和提示只在明确交互后短暂出现。微光允许采用需要学习的手势或点击区域，不要求所有能力常驻为可见按钮；普通播放器始终提供完整的可见操作作为替代。

### 2.4 设置

设置只保存低频调整，不与“继续播放”或当前媒体卡片混在一起。至少分为：

- 微光显示与重新校准；
- 字幕外观；
- 微光交互说明；
- 内容来源、扫描和数据管理；
- 关于与诊断。

## 3. 内容管理

本地扫描正式进入产品范围。内容管理的目标不是复制一个庞杂的音乐商店，而是让用户在几步内找到内容、建立播放顺序并再次回来。

### 3.1 内容概念

以下概念分工明确，不把它们混成同一层级：

- **媒体条目**：可播放的歌曲、录音、播客或视频音轨，是内容库的基本对象；
- **专辑、歌手、文件夹**：描述和浏览媒体的不同维度；
- **来源**：内容从哪里被发现或授权，例如系统媒体目录、用户选择的文件夹或单独打开的文件；
- **播放列表**：用户长期保存的内容集合；
- **播放队列**：这一次实际将要播放的顺序；
- **历史与进度**：帮助用户继续上次和快速回到最近内容。

“专辑”“歌手”“文件夹”和“来源”都是同一批媒体的浏览入口，不复制出多份内容。来源同时记录访问状态；文件移动、删除或授权失效时，条目可以重新定位或移除，不以崩溃处理。

### 3.2 内容进入方式

首批支持两条互补路径：

1. 扫描系统可见的本地音频，建立可搜索和分类的内容库；
2. 继续支持用户主动选择文件或授权文件夹，覆盖系统媒体目录没有收录的内容。

首次使用内容库时解释扫描范围和所需权限。用户拒绝扫描权限后，单文件与文件夹选择仍然可用；应用不把授权作为进入播放器的强制门槛。

扫描和刷新应当增量、可恢复，不复制大型媒体文件。相同内容尽量只展示一次，同时保留其来源与可用状态。

### 3.3 快速整理

内容库优先提供：

- 按标题、歌手、专辑、最近加入和时长排序；
- 按歌曲、专辑、歌手、文件夹和来源浏览；
- 全库搜索；
- 添加到播放列表；
- 下一首播放、添加到队列和立即播放；
- 保存媒体与外部字幕之间的关联。

批量标签编辑、复杂智能列表和自动联网补全暂不进入第一轮。

## 4. 播放器能力

### 4.1 队列与播放列表

从歌曲、专辑、歌手、文件夹或播放列表开始播放时，都形成一个明确队列。用户可以：

- 查看当前项和接下来内容；
- 调整顺序或移除队列项；
- 选择“下一首播放”或“添加到队列”；
- 切换随机、单曲循环和列表循环；
- 保存和编辑长期播放列表。

队列与播放列表不是同一个概念：队列属于当前播放过程，播放列表属于用户保存的内容组织。

### 4.2 睡眠定时

睡眠定时是夜间场景的核心能力，不藏在通用设置深处。至少支持：

- 常用分钟数；
- 当前内容播放结束后停止；
- 查看剩余时间；
- 随时延长或取消。

定时结束后应停止播放并清楚结束当前计时，不在下次播放时静默沿用旧定时。

### 4.3 播放恢复与系统控制

应用保存当前队列、当前媒体、播放位置、倍速、播放模式、字幕选择和字幕偏移。冷启动、Activity 重建或服务恢复后，用户能够继续上次状态。

播放器继续由同一个后台 MediaSession 持有：

- 离开界面或关闭屏幕后音频可以继续；
- 通知、锁屏、耳机和蓝牙控制保持同步；
- 耳机断开、音频焦点变化和播放错误遵循可预测的恢复行为；
- 视频容器只播放音轨，不建立视频画面。

## 5. 视觉语言

视觉目标不是“深色 Material”，而是让界面像从 OLED 黑色中短暂浮现，并在不需要时重新消失。

### 5.1 基础规则

- 全局以纯黑为主要背景，必要层级只使用克制的灰阶差异；
- 尽量不用大块强调色、彩色卡片、渐变背景和大面积填充按钮；
- 主要依靠排版、间距、透明度、细分隔和少量动效建立层级；
- 品牌黄色只用于当前选择、进度、焦点或少数关键动作，不铺成整块背景；
- Logo 用于启动、空状态、关于和少量品牌时刻，不要求每个页面围绕 Logo 配色；
- 封面存在时保持克制，不用封面取色覆盖整个播放器；
- 页面和系统栏尽量边到边融合，减少“套在系统页面模板里”的感觉；
- 动效以淡入、淡出和位置过渡为主，不制造持续发光装饰。

普通界面仍要保持清楚可读和足够大的触控目标；低亮度只属于微光，不把整个应用压暗到难以操作。

### 5.2 发光预算

每个常驻视觉元素都应回答：它是否在当前时刻帮助用户找到内容、判断状态或完成操作？如果不是，就应移除或延后出现。

微光状态尤其遵循：

- 黑色区域不放装饰；
- 字幕 gap 不保留上一句残影；
- 无字幕时不为了“填满页面”增加频谱、封面或动画；
- 临时控制可以比字幕更清晰，但不使用大块亮色表面；
- 来电、闹钟和系统浮层属于平台行为，应用自身不制造额外亮屏。

## 6. 微光锁定与交互

### 6.1 状态

微光至少区分两个日常状态：

1. **沉浸锁定**：只显示字幕或纯黑，普通单次触碰不会弹出整块控制；
2. **临时操作**：通过明确手势解锁，显示低发光控制，并在无操作后重新锁定。

首次进入微光时用很短的示意说明如何播放、快退、快进、解锁和退出。说明可在设置中再次查看。

### 6.2 手势原则

微光可以使用全屏点击区域、双击、长按或少量方向手势，让熟悉后的操作不依赖可见控件。具体映射先通过真机原型确定，遵守以下原则：

- 偶然碰到屏幕不会立即铺开操作栏；
- 左、中、右区域的含义稳定且容易形成肌肉记忆；
- 播放暂停、快退和快进可以在锁定态完成，并给出非常克制的反馈；
- 打开完整控制和退出微光需要更明确的操作；
- 不在第一版叠加过多上下滑、亮度、音量等隐藏手势；
- 音量键继续遵循系统行为；
- 普通播放器保留所有对应的可见按钮。

第一版优先验证的候选是“左右区域双击快退/快进、中间区域双击播放/暂停、长按进入临时操作”，最终映射以误触率和真机体验为准。

锁定是应用内的防误触状态，不宣称为系统锁屏或 AOD，也不拦截来电、闹钟和系统安全行为。

### 6.3 临时操作

临时控制只容纳当前最需要的动作：

- 快退、播放或暂停、快进；
- 当前进度和时间；
- 睡眠定时状态；
- 字幕偏移快捷调整；
- 返回普通播放器。

队列编辑、字幕外观和来源管理返回普通界面完成，不把微光重新变成完整设置页。

## 7. 校准与字幕外观

当前混在一起的窗口亮度、文字亮度、控制亮度、字号和位置应拆成两个产品概念。

### 7.1 微光校准

正式版本在用户第一次进入微光前引导完成一次短校准：

- 使用真实纯黑全屏和示例文字；
- 调整微光窗口亮度；
- 找到当前设备上刚好可读的文字亮度；
- 调整临时控制相对亮度；
- 立即预览锁定态与临时操作态的差异；
- 保存为当前设备默认值，并允许以后重新校准。

界面使用“更暗”“更清晰”等直观语言和实时结果，不把百分比或 RGB 数值作为主要交互。

### 7.2 字幕外观

字幕外观独立设置并使用实时示例预览，包含：

- 字号与字重；
- 行距和对齐；
- 垂直位置；
- 主次文字或双语布局；
- 长句换行效果。

没有真实字幕时仍使用示例文本预览。字幕外观不改变播放器窗口亮度，微光校准也不替用户决定字幕排版。

## 8. 现有基础与实施方向

现有原型已经提供可继续复用的基础：

- Media3 `MediaSessionService` 与 ExoPlayer 后台播放；
- 通知控制、基础生命周期和最后会话恢复；
- Storage Access Framework 单文件选择；
- SRT、LRC、WebVTT、ASS/SSA 解析与统一时间轴；
- 字幕偏移、倍速和基础微光亮度控制；
- Vivo Android 16 上的首轮真机 smoke test。

下一阶段不重写这些已经验证的能力，而是在其上扩展内容集合、队列与新的产品表面。

工程继续保持单一 `app` 模块、Kotlin、Compose 和 Media3。内容库、播放列表和恢复需要什么存储，就按实际查询与一致性需求选择最简单可靠的方案；不为了形式预先引入多模块、DI 框架或复杂 repository 层。

播放器状态仍以后台 Player / MediaSession 为唯一播放真相。媒体文件不因扫描或播放被复制到应用目录，字幕小型规范化副本和可重建元数据继续按需要保存。

## 9. 下一阶段顺序

### 9.1 产品框架与视觉重置

- 建立纯黑、低色块的全局视觉基础；
- 将首页重组为内容库入口；
- 将显示校准和字幕外观移出当前会话卡片；
- 允许无字幕进入微光；
- 保留当前单文件入口作为内容库尚未完成时的可用路径。

### 9.2 内容管理与播放器补全

- 本地媒体扫描、文件夹授权与刷新；
- 歌曲、专辑、歌手、文件夹和来源浏览；
- 搜索、最近内容和播放列表；
- 播放队列、上一项/下一项、随机与循环；
- 睡眠定时；
- 队列和播放状态恢复。

### 9.3 微光体验收口

- 沉浸锁定与临时操作状态；
- 手势或点击区域的真机原型；
- 首次微光校准与实时预览；
- 独立字幕外观设置；
- 无字幕、字幕 gap、暂停、结束和错误状态；
- OLED 真机上的误触、亮度恢复和长时间体验验证。

这些阶段是实施顺序，不要求拆成复杂的工程里程碑。每一阶段保持应用可运行，并优先完成能够真实使用的纵向路径。

## 10. 下一阶段完成标准

- 用户可以扫描或主动导入本地内容，并快速搜索或分类找到它；
- 从歌曲、专辑、歌手、文件夹或播放列表开始播放时形成正确队列；
- 上下项、队列编辑、随机、循环、倍速和睡眠定时可用；
- 应用重建后可以恢复当前队列、媒体、位置和必要设置；
- 有无字幕都能进入微光；
- 微光锁定后偶然单击不会弹出大块控制，主要手势可以稳定完成；
- 首次校准和字幕外观调整都有真实、直观的实时预览；
- 普通页面以纯黑和灰阶为主，没有大面积品牌色或不必要发光表面；
- 后台、通知、锁屏、耳机断开和窗口亮度恢复继续通过真机验证。

## 11. 验证原则

默认运行与改动直接相关、范围最小的检查，再按风险扩大：

- 内容索引、队列顺序、播放模式、定时结束和恢复规则使用自动测试；
- 字幕 parser 与时间轴继续使用纯 Kotlin 单元测试；
- 服务、Manifest、媒体权限或 MediaController 改动至少运行相关构建检查；
- 扫描授权、后台播放、通知、锁屏、耳机断开和睡眠定时必须做真机 smoke test；
- 微光必须在 OLED 真机验证亮度、系统栏恢复、无字幕、误触和手势可学习性；
- 无法运行的检查明确记录原因和未覆盖风险。
