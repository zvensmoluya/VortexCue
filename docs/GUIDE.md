# VortexCue / 荧荧产品指南

> 状态：当前唯一的产品与实施指导
>
> 当前阶段：M3 退场式播放与个人内容闭环
>
> 长期背景：[`DOMAIN_CONTEXT.md`](DOMAIN_CONTEXT.md)
>
> 更新时间：2026-08-11

本文定义当前要实现和验收的产品行为。`DOMAIN_CONTEXT.md` 解释荧荧为什么存在，但不自动产生实现要求；研究报告用于提供证据和假设，也不直接覆盖本文。

荧荧是一款 Android-first、OLED-first、sleep-first 的本地内容播放器。它服务的是已经躺下、仍想继续听本地 ASMR、voice work、长视频、访谈、课程或其他长内容，却不再需要整块屏幕持续存在的人。

> **内容继续，屏幕退场；当视觉信息仍有价值时，只让当前同步文字发光。**

字幕不是播放硬门槛，但也不是媒体旁边的可选装饰。它是界面退场后仍值得保留的最小视觉内容，尤其服务跨语言理解、没有听清和需要当前语境的时刻。

## M3 目标

M3 证明的不是一个只能打开单文件的工具，而是一条从首次价值进入长期使用的完整产品闭环：

> **今晚可以直接打开，明晚可以从这里继续；值得再听的内容不必重新回到 Android 文件系统寻找。**

首次或临时使用路径是：

```text
首次样片或 Home
        ↓
打开一个内容
        ↓
发现或选择可用同步文字
        ↓
字幕中心 Normal Player
        ↓
界面逐渐退场
        ↓
Glow / 纯黑
        ↓
Sleep Timer / 退出
        ↓
进入最近并保存可恢复会话
        ↓
按用户决定加入“我的内容”
```

重复使用路径是：

```text
Home
  ↓
继续上次 / 今晚 / 我的内容
  ↓
Normal Player → Glow
  ↓
下一次从同一内容、位置、队列和表面继续
```

### M3 完成条件

- 用户不需要扫描整台设备或建立资源库，就能打开一个本地媒体并开始播放；
- 打开过一次的内容可以进入最近和 Continue，但不会因此自动等同于“已收录”；
- 用户可以把跨文件夹、跨来源的内容明确加入“我的内容”，冷启动时无需重扫即可找到；
- 用户只需选择一次常用文件夹，之后可以在荧荧内看到其已缓存的发现结果并按需刷新；
- 文件夹或设备扫描结果可以立即播放，收录和忽略不是播放前置步骤；
- 用户可以从不同来源挑选多个内容形成“今晚”，并恢复其顺序和当前项；
- 有可用同步文字时，用户能确认当前文字轨、进入字幕中心播放器并进入 Glow；
- 没有同步文字时仍能正常播放和进入退场状态，但产品不把纯黑播放当作主要差异化表达；
- 用户退出后，媒体、位置、文字轨、偏移、显示选择和最后表面可以恢复；
- 上次退出于 Glow 时，Home 通过一次明确操作直接继续 Glow，不必先经过 Normal Player；
- 单文件和明确授权的文件夹不经过“必须整理完才能播放”的流程；
- 全设备扫描只存在于“更多来源”，不在冷启动前台自动执行，也不阻塞 Home；
- 后台播放、通知、锁屏、耳机、蓝牙和 Sleep Timer 保持可靠；
- 至少完成一次创作者连续七晚真实内容使用，区分一次惊艳与重复习惯。

### M3 非目标

以下能力在获得新行为证据前不扩展：

- ASR、自动翻译和 TransVortex 消费端接入；
- 在线字幕搜索、在线内容目录、推荐和社交；
- Artist、Album、封面、EQ 和完整音乐资料库；
- 自动移动、重命名、复制或删除用户文件；
- 常驻后台全盘索引和无需用户意图的自动扫描；
- 收藏、标签、复杂合集、命名 Playlist 和完整音乐资料库管理；
- Shuffle 和通用播放器功能补齐；
- 视频观看 Surface；
- 完整 transcript 阅读器、字幕编辑器和逐词动画；
- 账号、云同步和商业订阅体系。

M3 会建立最小但真实的“我的内容”和“今晚”。现有 Queue、Playlist、Library 和扫描代码不删除，但必须逐步迁移到清晰的 Source、Collection 和 Session 边界；已有实现不自动决定最终产品结构。

## 产品原则

- **首次价值不等待整理**：先让用户播放今晚这一份内容，再决定是否长期收录。
- **个人内容集是长期价值**：Android 文件系统负责文件在哪里；荧荧负责哪些内容值得再次夜听。
- **Folder 不等于我的内容，我的内容不等于今晚**：来源、长期选择和当前消费顺序分别建模。
- **只管理引用和关系**：荧荧保存授权、索引、字幕关系、播放状态和用户决定，不移动、重命名或删除原文件。
- **消费方式优先于格式**：音频和视频都可以是主要通过声音消费的长内容。
- **界面允许退出**：越接近睡眠，产品要求用户观看和操作的内容越少。
- **同步文字是正在发生的内容**：优先显示当前 cue，不默认完整 transcript 更高级。
- **字幕优先但不强制**：有字幕时充分发挥它的价值，没有字幕时播放仍然成立。
- **用户选择优先于算法**：手动选择过的文字轨永久压过自动规则，直到用户主动恢复自动选择。
- **本地与最小授权**：文件留在原位置；单文件、文件夹和系统媒体权限按真实任务逐步请求。
- **发现不等于收录**：能够扫描不代表用户希望收录；收录也不应成为播放门槛。
- **播放器能力必须有场景理由**：Continue、快退、Sleep Timer 和媒体控制因睡前任务保留，不因“播放器通常都有”而扩张。
- **低发光而非护眼承诺**：使用“低发光”“减少发光面积”“低环境干扰”，不使用“护眼”“零伤害”或“保证睡眠”。

## 三层产品模型与核心对象

荧荧明确区分三层长期职责：

```text
Source / 来源
文件在哪里，应用拥有什么访问权限
        ↓
Collection / 我的内容
哪些内容是用户明确留下、希望再次找到的
        ↓
Session / 今晚
这一次准备按什么顺序消费，以及当前进行到哪里
```

三层之间不是替代关系：

> **Folder != My Content != Tonight**

- Source 可以是单文件、SAF Folder、MediaStore 或未来的 Share / Open With；
- 一个 Source 中可以同时存在已收录、未收录和已忽略内容；
- “我的内容”可以跨越多个物理来源；
- “今晚”可以临时组合多个已收录或尚未收录的内容；
- 移除 Source、移出“我的内容”或清空“今晚”都不删除原文件。

M3 的核心领域对象是：

```text
ContentSource
├─ uri / type / displayName
├─ persistedPermission
├─ scanState / lastIndexedAt
└─ accessState

PlayableContentUnit
├─ stableId
├─ media
├─ sourceId
├─ timedTextTracks[0..N]
│  ├─ embedded
│  ├─ sidecar
│  ├─ lyrics
│  └─ generated        future
├─ activeText
│  ├─ primary
│  └─ secondary?       optional
└─ textState
   ├─ offset
   ├─ manualSelection
   └─ rejectedCandidates

CollectionEntry
├─ contentId
├─ collectedAt
└─ availability

RecentEntry
├─ contentId
├─ lastOpenedAt
├─ position / duration / speed
└─ lastSurface

TonightQueue
├─ contentIds[]
├─ currentIndex
└─ completionState
```

同一个 `PlayableContentUnit` 可以同时出现在最近、我的内容和今晚；这些是相互独立的关系，不复制媒体文件。打开一次只产生 `RecentEntry` 和可恢复会话，只有明确收录才产生 `CollectionEntry`。

用户界面不出现 `PlayableContentUnit`、`CollectionEntry`、`Session` 或匹配置信度等内部术语。用户只看到：

- 最近；
- 我的内容；
- 今晚；
- 字幕；
- 来源；
- 睡眠定时。

现有 `MediaSourceRef + SubtitleAssociation + LibraryConfig + RestorableSession` 作为迁移起点。M3 不要求一次性重写全部持久化，但新模型必须版本化、兼容旧数据，并避免继续把“打开过”“已收录”和“正在播放”写进同一个列表。

## 应用结构

```text
首次体验
├─ 体验短样片
├─ 打开自己的内容
└─ 添加常用文件夹

Home / 今晚的启动台
├─ NOW
│  ├─ 继续上次
│  └─ 今晚队列
├─ MINE
│  └─ 我的内容窗口
└─ MORE
   ├─ 新发现
   └─ 添加内容或来源

我的内容
├─ 最近
├─ 已收录
├─ 搜索
└─ 来源入口

来源与发现
├─ 已授权文件夹
├─ 可选设备媒体扫描
├─ 新发现 / 已忽略
└─ 刷新与权限状态

Normal Player
├─ 当前字幕语境
├─ 基础播放控制
├─ 字幕轨与同步
├─ 今晚、Queue 与 Sleep Timer
└─ 进入 Glow

Glow
├─ 当前同步文字
├─ 字幕间隙 / 无字幕纯黑
├─ 沉浸锁定
└─ 临时操作
```

Home 不是完整资源库浏览器，“我的内容”也不是隐藏在高级管理页里的底层能力。M3 可以先用一个页面承载这些区域，不提前锁定底部导航；信息层级必须稳定为 `NOW → MINE → MORE`。

## 首次体验

首次启动不先请求全设备媒体权限，也不要求建立资源库。

主路径使用一份可合法随应用分发、长度约一分钟的样片，直接证明：

```text
声音和时间继续
        ↓
完整播放器退场
        ↓
只剩当前同步文字
        ↓
字幕间隙回到纯黑
```

微光亮度校准嵌入第一次样片 Glow，不建立独立的多步骤设置向导。目标是“清晰、舒适、不费力”，不是越暗越好。

用户可以跳过样片并直接打开自己的内容。首次样片、亮度校准和打开文件都不得依赖全盘媒体权限。

## Home、继续与今晚

Home 是“今晚的启动台”，按顺序回答三个问题：

1. 我上次进行到哪里、今晚是否已有安排；
2. 我长期留下了哪些值得再听的内容；
3. 新内容从哪里进入。

### Active Session

首页最强位置只保留一个动态 Active Session 区域：

- 单个内容未完成时显示“继续上次”；
- Tonight 已开始时显示“今晚继续”、当前项和接下来的内容；
- Tonight 已准备但尚未开始时显示“开始今晚”；
- 没有会话时不显示空卡片，由打开内容和添加来源承担首次动作。

继续区域至少显示：

- 内容标题与 Tonight 中的位置；
- 上次播放位置；
- 当前字幕语言或“无字幕”；
- 上次表面是 Normal 还是 Glow；
- 当前文件不可用时的明确恢复状态。

应用冷启动本身不自动播放。用户点击“继续”是明确播放动作：

- 上次表面为 Glow 且媒体、文字关系仍有效时，直接恢复 Glow；
- 上次表面为 Normal 时，恢复 Normal；
- 媒体或字幕不可读时进入可解释的修复流程，不静默丢失字幕；
- 不要求用户先重新进入来源、重新扫描或重新收录内容。

### 我的内容窗口

Home 只展示“我的内容”的小型窗口，例如数量、最近使用和少量条目；完整浏览、搜索和收录管理进入“我的内容”。它不是首页的全部，也不能被降级成只有进入管理页才能找到的隐藏能力。

### Progressive Home

Home 随用户状态逐渐生长：

```text
首次：样片 / 打开内容 / 添加文件夹
已有内容：继续 / 我的内容 / 添加
已有 Tonight：今晚继续 / 接下来 / 我的内容
```

首次空状态保留“打开一个内容”和“添加常用文件夹”的明确文字入口。“扫描设备媒体”不得成为第一 CTA。用户已经形成稳定内容集后，可以把低频添加动作收进统一入口，但不在 M3 提前锁定具体按钮形式。

## 内容进入路径

### 打开一个内容

单文件是最快的高意图路径：

```text
选择媒体
   ↓
恢复已记忆关系
   ↓
发现内嵌文字轨
   ↓
使用已选外挂字幕，或按需手动选择
   ↓
Normal Player
```

- 音频和视频均可打开；视频只提供音轨、时间和文字轨，不创建观看 Surface；
- 单文件打开后直接形成可恢复内容并进入最近，不进入待整理，也不自动加入“我的内容”；
- 播放前后都可以明确执行“加入我的内容”，该动作只保存应用内引用和关系；
- 没有字幕不阻止播放；
- 单文件授权不能可靠枚举相邻文件，需要自动发现外挂字幕时再邀请用户选择包含内容的文件夹；
- 用户以后可以在播放现场查看、更换、移除或恢复自动字幕选择。

### 打开一个文件夹

明确授权的小文件夹是来源边界，也是系列内容和外挂字幕的自然发现范围：

```text
选择文件夹
   ↓
扫描这个授权范围
   ↓
发现媒体和文字轨
   ↓
建立高置信关系
   ├─ 立即播放
   ├─ 收录到我的内容
   └─ 忽略
```

- 扫描结果立即可以播放，不要求先完成整理或收录；
- 添加 Folder 后保存 SAF 授权和可重建索引，用户不应每晚重新经过系统文件选择器；
- Folder 是 Source，不自动等同“我的内容”，其内部可以同时有已收录、未收录和已忽略内容；
- 已缓存索引必须能在冷启动时显示；刷新由用户明确触发或在进入来源时非阻塞执行；
- 收录支持逐项和批量操作，但不得把整个文件夹默认视为用户认可的消费集合；
- 同目录完全同主文件名可以高置信关联；
- `.zh`、`.en`、`.ja`、`.forced`、`.sdh`、`.cc` 等后缀作为语言或角色信息保留；
- 多个候选全部保留，不选择“最短文件名”后丢弃其他轨；
- 不明确的候选只建议，不自动激活；
- 深层或大型目录必须避免阻塞 Home，并提供可见的扫描状态和取消能力。

### 来源、发现与我的内容

“我的内容”保存用户明确认可的跨来源内容；来源页负责文件夹、MediaStore 和访问状态；“新发现”负责尚未决定的索引结果。三者不能继续混成一个资源库管理页。

全设备 MediaStore 扫描继续作为低频可选来源，不能代表“我的内容”，也不能因为平台允许访问就自动运行。

只有广泛扫描继续使用：

```text
扫描发现
→ 立即可播放的新发现
→ 按用户决定收录或忽略
```

M3 不在冷启动时自动执行全设备扫描，也不递归重新检查全部授权文件夹后才显示 Home。冷启动恢复持久目录、来源快照和当前会话，并按需验证当前需要访问的 URI；重扫由用户明确触发，或在进入对应来源时以不阻塞主路径的方式执行。

新发现保持安静：它可以在 Home 显示数量和来源，但不使用警告语气，也不阻塞 Continue、Tonight 或播放。用户不处理 Inbox 时，已收录内容仍然稳定可用。

广泛扫描仍遵守：

- 发现不等于收录；
- 打开和播放也不等于收录；
- 视频默认不选；
- 已忽略内容不反复打扰；
- 移出“我的内容”、忽略条目、移除来源和清空 Tonight 都不删除原文件；
- 应用不提供移动、重命名和整理磁盘目录的文件管理操作；
- 收录条目的媒体快照、文字关系和用户决定必须持久化，不能依赖下次扫描重建后才出现；
- 部分媒体权限范围必须清楚可见；
- MediaStore 字幕索引只能作为补充发现来源，不作为全部文字关系的真相。

## 同步文字发现与选择

字幕发现和字幕激活是两个不同决定：

```text
发现文字轨
    ↓
判断它是否属于当前媒体
    ↓
建立候选关系
    ↓
判断用户现在要看哪一轨
    ↓
激活 primary / secondary
```

优先级如下：

| 来源 | 自动建立关系 | 自动激活 |
| --- | --- | --- |
| 用户此前手动选择 | 是 | 是，最高优先级 |
| 容器内嵌文字轨 | 是 | 明确 default 或符合已知语言偏好时 |
| 同目录完全同 stem 外挂字幕 | 是 | 唯一候选且无手动选择时 |
| 带语言/角色后缀的同名字幕 | 全部保留 | 有明确语言偏好时，否则询问 |
| 可解释的剧集或版本候选 | 只建议 | 否 |
| 模糊文件名或跨目录候选 | M3 默认不出现 | 否 |

每条文字轨至少能够表达：

- 来源：内嵌、外挂、歌词或未来生成；
- 格式和 URI；
- 语言、名称和角色；
- 是否 default、forced、SDH/CC；
- 匹配依据；
- 是否由用户手动选择；
- 是否曾被用户拒绝；
- 当前是否可读和可解析。

M3 保留现有 SRT、LRC、WebVTT、ASS 和 SSA 外挂字幕解析。内嵌文本字幕应接入同一时间轴；图形字幕不应伪装成可用于 Glow 的文本轨。

自动关系读取或解析失败必须显示可恢复状态，并允许重新选择。已有字幕时，Normal Player 仍必须提供查看、切换、更换和移除入口。

## Normal Player

Normal Player 是用户确认内容、理解当前语境和进入退场状态的地方，不复制传统音乐播放器的封面中心布局。

字幕区域按以下层级组织：

```text
上一句          弱
当前句          主视觉
下一句          弱
```

M3 目标能力：

- 当前 cue 与播放时间严格联动；
- 上一句、当前句和下一句提供必要上下文；
- 支持重听当前句或点句跳转；
- primary / secondary 可以独立选择和显示；
- 主次语言拥有独立但克制的视觉层级；
- 字幕 offset 可以调整和重置；
- 当前已有字幕时也能直接管理文字轨；
- 字幕缺失或失败时给出明确的添加或修复动作；
- 进入 Glow 是有同步文字时的主要退场动作。

完整可滚动 transcript、全文搜索和逐词高亮不是 M3 完成条件。它们只有在真实长内容使用证明上下文浏览不足时再进入范围。

普通播放器仍保留：

- 标题与必要元数据；
- 可拖动进度；
- 播放或暂停、快退、快进和上下项；
- 倍速；
- Queue；
- Sleep Timer；
- 返回 Home。

视频容器只播放音轨并驱动文字时间轴。产品不提供视频观看界面。

## Glow

Glow 不是普通播放器隐藏控件后的皮肤，而是退场体验的沉浸表面：

- 有同步文字时只显示纯黑背景和当前 cue；
- primary / secondary 按用户选择显示，不强制双语；
- 字幕间隙不填充装饰、封面、频谱或提示；
- 没有同步文字时纯黑仍是合法退场状态；
- 无字幕 Glow 可以保留控制能力，但不取代“只让字幕发光”成为主要产品表达；
- 默认处于沉浸锁定，普通单次触碰不弹出完整操作栏；
- 左、中、右区域双击分别执行快退、播放或暂停、快进；
- 长按进入临时操作，数秒无操作后重新锁定；
- 临时操作只保留进度、基础控制、Sleep Timer、字幕偏移、文字轨和返回 Normal；
- 退出时保存当前表面，下一次可以直接继续 Glow。

Glow 锁定只防止应用内误触，不冒充系统锁屏或 AOD，也不拦截来电、闹钟和系统安全行为。

窗口亮度、字幕像素亮度和临时控制亮度保持独立。普通界面保持清晰可读，低亮度只属于 Glow。

## 播放、今晚与 Sleep Timer

`PlaybackService` 内的 Player / MediaSession 是播放状态唯一真相。离开界面、关闭屏幕或应用进程重建时，应用层不建立第二套播放事实。

Continue 至少保存：

- 当前媒体；
- 播放位置和已知时长；
- 倍速；
- Queue 与当前项；
- Repeat / Shuffle 的现有状态；
- active primary / secondary；
- 字幕 offset；
- 最后 Normal / Glow 表面；
- Glow 显示配置；
- URI 可用性和修复信息。

Sleep Timer 至少支持：

- 常用分钟数；
- 当前内容结束后停止；
- Tonight 队列结束后停止；
- 剩余时间；
- 取消；
- 在 Normal 和 Glow 中均可低摩擦进入。

“今晚”是用户可在播放前准备、跨来源编辑并在 Home 继续的当前消费意图；Player Queue 是它开始播放后的运行时表达。两者不能继续只作为播放器内部状态存在。

M3 的 Tonight 规则是：

- 可以从我的内容、新发现或单次打开内容中加入；
- 支持查看顺序、移除和重排，不要求创建或命名 Playlist；
- 当前项未完成时，第二天保留当前项和后续项；
- 已完成项可以从下一次启动视图中收起，但保留必要的最近记录；
- Tonight 全部完成或用户明确清空后回到无当前计划状态；
- 当前项切换时恢复该内容自己的文字轨、offset、进度和显示选择；
- 单内容播放仍是合法的退化情况，不强迫用户先建立 Tonight。

Folder 的自然顺序、现有 Playlist 或用户明确选择的多个内容都可以为 Tonight 提供初始顺序。复杂命名播放列表不是 M3 目标。

## 视觉语言

- 全局使用 OLED 纯黑背景，层级主要依靠排版、间距、透明度和细分隔；
- 不使用大块强调色、彩色卡片、渐变背景和装饰性发光；
- 品牌黄色只用于当前选择、进度、焦点和少数关键动作；
- Logo 只出现在启动、关于或真正需要品牌识别的时刻；
- 主界面不反复解释产品功能或展示操作说明；
- 页面与系统栏尽量融合，减少套用系统模板的感觉；
- 动效以淡入、淡出和克制的位置变化为主；
- 普通界面保持清晰和足够触控面积，低亮度只属于 Glow；
- 每个常驻元素都必须帮助用户开始、理解、控制或继续当前内容。

## 工程边界

工程继续保持单一 `app` 模块，不为目录整齐提前拆分 Gradle 模块。Kotlin 包按职责组织：

```text
app       Activity、应用组合根与系统入口
core      内容体验单元、共享模型与存储格式
library   Source、发现索引、我的内容、Folder 与持久化
playback  MediaSessionService、Active Session、Tonight Queue 与 Sleep Timer
subtitle  文字轨发现、读取、解析、时间轴与缓存
ui        首次体验、Home、Player 和主题
```

- `PlaybackService` 内的 Player / MediaSession 是播放状态唯一真相；
- 后台播放服务只接受本应用和系统认可的可信控制器，应用私有命令不向外部控制器开放；
- `app` 连接系统入口和功能状态，不重新实现来源、字幕或播放规则；
- Home 不直接拥有扫描和内容关系算法；
- “我的内容”只操作应用内目录和用户关系，不直接执行文件系统删除、移动或重命名；
- 扫描、匹配、轨道排序、迁移和恢复规则保持为可测试的纯逻辑；
- 当前资源库配置和用户决定必须向后兼容，不进行破坏性清空；
- 媒体文件不复制到应用目录；授权、来源快照、内容目录、用户关系和小型文字缓存可以持久化；
- 只有出现真实构建、隔离或复用需求时才增加 Gradle 模块。

## 验证与决策

### 自动化验证

改动相关范围至少覆盖：

- 单文件打开进入 Recent 但不自动进入 Collection；
- 收录内容和来源快照可以在不扫描的冷启动中恢复；
- 旧 `manualItems`、收录决定和最后会话迁移不丢失；
- 文字轨匹配和排序；
- 手动选择压过自动规则；
- 被拒绝候选不会重新自动激活；
- 旧字幕关联向新模型迁移；
- Tonight / Queue 切换恢复每项文字关系和进度；
- Tonight 在进程重建后保留顺序、当前项和未完成项；
- `lastSurface`、位置、offset 和显示状态恢复；
- 广泛扫描不会由普通冷启动触发。

### 真机验证

涉及以下行为必须使用真实 Android 设备：

- 单文件和 SAF Folder 授权；
- 打开一次、明确收录、移出我的内容和原文件仍存在；
- 从已授权 Folder Source 再次进入时不重新经过系统文件选择器；
- 从多个来源加入 Tonight、重排、跨项播放和第二天恢复；
- 内嵌与外挂文字轨；
- 后台 MediaSession、通知、锁屏、耳机和蓝牙；
- 进程重建与 URI 失效恢复；
- Normal → Glow → Continue；
- OLED 纯黑、字幕 gap 和亮度；
- Sleep Timer 与内容结束；
- 大 Folder 扫描的取消和非阻塞表现。

### 决策分支

- **Go**：用户理解它与锁屏、视频播放器的区别，并用自己的内容重复进入 Glow；
- **Rework A**：喜欢 Glow，但大量内容没有字幕，下一步验证 ASR、TransVortex 或翻译供给；
- **Rework B**：喜欢睡前播放但很少看字幕，继续强化 sleep-first，字幕保留为差异能力；
- **Rework C**：Glow 成立但 Android 文件查找和跨来源选择仍重，优先改善 Source、我的内容和 Tonight，不扩展通用音乐库；
- **Rework D**：用户主要依赖 Recent / Continue，几乎不主动收录或建立 Tonight，收缩对应表面但保留底层关系；
- **No-Go / 重新定位**：充分体验后仍普遍选择直接锁屏，或 Glow 只产生一次新奇而没有第二次使用。

在完成 M3.5 的真实夜间使用前不开始 M4，也不以更多案头研究替代行为验证。M3.2 之后每个里程碑都必须带真实内容走通，不等待全部结构完成后再测试。
