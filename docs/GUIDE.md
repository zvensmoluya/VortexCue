# VortexCue 产品与实施指南

> 本文是当前 UI、信息架构和实现边界的最高产品规格。
> `docs/reference/UI_LAYOUT_DESIGN.md` 记录布局与交互细节；`docs/reference/布局原型.html` 仅保留结构参考，不代表视觉风格。
> 长期领域背景见 [`DOMAIN_CONTEXT.md`](DOMAIN_CONTEXT.md)。

VortexCue 是 Android-first、OLED-first、sleep-first 的本地内容播放器。核心价值是“内容继续，屏幕退场；需要视觉时只显示当前同步文字”。字幕不是播放前置条件，但在 Normal Player 与 Glow 中是最小、可读、可退出的视觉内容。

## 1. 应用壳层

一级页面固定为四个：

```text
歌单 | 播放列表 | [骨白荧荧 Logo：Import Hub] | 配置 | 设置
```

Logo 是动作，不是第五个页面；点击只打开 Import Hub，不改变当前 Tab。歌单页承担默认进入位置，但 UI 不使用“首页”命名，也不再出现 Home、今晚、发现或来源一级入口。

存在 Current Queue 时，Mini Player 跨四个 Tab 显示。Mini Player 是与底栏连续的全宽播放坞，不复用歌单卡片轮廓；它只显示标题、已播放时间、剩余时间、播放状态标记和播放/暂停，时间直接表达当前播放位置，不另设重复的进度条。播放时状态标记轻微起伏、顶边微光和按钮光晕缓慢呼吸，暂停时归静，缓冲时按钮外显示细弧；出现、退场、切歌与播放图标切换使用短促克制的过渡。播放按钮使用独立圆形承载面，点击播放坞正文只进入 Normal Player，不改变播放状态。它不显示同步文字、Sleep Timer 或额外播放操作。冷启动不恢复 Glow，Glow 只能由当前运行期的 PlayerSurface 明确进入。

应用内视觉令牌：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| Background | `#000000` | 页面与 Glow 背景 |
| Primary text | `#EEF0F4` | 月白主文字 |
| Secondary text | `#A39EAF` | 冷紫灰次要文字 |
| Raised surface | `#17151D` | Bottom Sheet、对话框、控件层 |
| Hairline | `#2A2732` | 细分隔线 |
| Selection | `#282432` | 当前项与选中态 |
| Mascot | `#E8E0D0` | 中央骨白 Logo |

黄色不进入应用内 UI；Launcher 与 Splash 保留既有品牌资源。当前歌单不使用封面、拼贴或文件夹图标，最多 8dp 圆角。普通浏览页允许使用 Raised Surface 与较高文字对比度；极低发光只约束 Glow 等退场阶段。交互控件最小 48dp 触控区，图标按钮必须有 TalkBack 描述；拖动、长按等动作同时提供可访问的替代操作。

## 2. 作品、歌单与全部内容

完整分发包可以形成一等 `Work`。作品表达发行方已经确定的消费单元，包含完整 Part 清单、正篇/特典区段、语义版本、格式 locator 和作品级继续进度；物理目录只作为识别发行清单的证据，不成为应用内导航。可信作品确认后完整收录，不在导入阶段逐文件筛选。收录只建立本地索引和关系，不复制、移动或上传原媒体。歌单表达用户跨作品的主观编排，与物理文件夹和 Source 完全独立。每个已收录内容必须由至少一个 Work 或真实歌单持有。

歌单页在“最近听过”之后展示“全部歌单”列表；列表中的作品与默认收藏、用户歌单使用同一层级和卡片密度，作品只通过副标题标明其特殊类型。作品是歌单的一种特殊形式：它由发行包自动形成，拥有完整的段落、版本和特典。整部 Work 在已有歌单引用中只占一个位置，播放时按“当前正篇版本 + 共享特典”展开为扁平 Current Queue；单段 Content 引用固定语义内容。作品详情只保留作品身份、版本切换和发行段落，不提供整部加入歌单或选择段落操作，也不展示顶部统计、上次进度或继续播放按钮；作品名与 RJ 身份相同时只显示一次，版本切换不另设标题或勾选图标，仅以选中底色区分。点击段落直接从该段开始播放。版本切换是整套正篇序列切换，不允许通过逐段勾选保存混合版本，点击后直接生效且不显示切换提示。

固定系统歌单“默认收藏”只是不属于 Work 的散装单文件安全落点，不可改名、删除或参与歌单排序。可信作品导入不选择目标歌单，也不进入默认收藏。歌单页不显示页面大标题和搜索。顶部“最近听过”最多横向展示 6 个最近真正从中开始播放的非空真实歌单；下面展示统一的“全部歌单”列表，其中包含作品、全部内容、默认收藏与用户歌单。当前版本不提供作品封面。

“全部内容”按 Work 和独立 Content 聚合，不平铺只由 Work 持有的 Parts；被用户单独引用到歌单的 Part 可以作为独立 Content 出现。它不写入 `playlist` 表，不能成为导入目标。歌单详情点击 Work 时从该入口展开作品，点击 Content 时播放该单项；“播放全部”按歌单入口顺序展开并按 `contentId` 去重。

从普通歌单移除 Content 的最后一个歌单归属时，如果它不属于 Work 才回退默认收藏；Work Part 可以保持零歌单归属。移除 Work 类型歌单入口只删除引用，不删除作品。移除作品时清理作品入口与作品级进度，仅由该 Work 持有的 Parts 移出内部内容集，仍被手动歌单引用的 Parts 保留；原文件始终不删除。

内容长按 Bottom Sheet 提供：

- 立即播放；
- 加入播放列表；
- 加入歌单；
- 从当前歌单移除（仅歌单详情）；
- 同步文字；
- 移出内容。

歌单详情右上角提供“整理内容”模式。进入后可以多选、全选，并批量“加入歌单”“移动到”或“从此移除”。“加入歌单”保留内容已有归属并支持多个目标；“移动到”只选择一个目标，把内容从当前歌单移出，但不影响它已有的其他歌单归属；批量移除沿用最后归属回退默认收藏和默认收藏唯一归属保护。全部内容没有来源歌单，只提供批量“加入歌单”。批量关系更新必须在单个数据库事务内完成，并反馈已更新、已存在和受保护数量。

“移出内容”只写入内部忽略状态，不删除原始媒体、不打断当前播放；来源刷新不会再次推荐。用户仍可从系统文件选择器显式选择同一文件，重新收录并立即播放。

## 3. Import Hub 与来源

底栏中央 Logo 打开临时全屏 Import Hub，不改变当前 Tab。流程只有“来源首页 / 来源详情”两层：详情返回来源首页，来源首页关闭后回到原 Tab。首次进入先说明音频发现用途并由“开始查找”请求音频权限；拒绝后不自动重弹，仅保留“再次允许”“选择音频或视频文件”“从其他位置查找音频”。Android 13+ 只请求 `READ_MEDIA_AUDIO`；旧系统即使使用宽泛存储权限，应用也只查询音频。

已授权时先展示持久缓存，并在每次打开 Import Hub 时后台刷新系统音频和已授权文件夹。刷新期间旧结果仍可浏览，显示进度与取消；失败或授权失效时保留旧索引并就地提供重试或重新授权。系统音频和已授权文件夹按扫描边界与规范化相对位置形成稳定来源卡片；路径末尾连续出现明确的音频格式、音质或 SE 变体目录时折叠到作品根，RJ 编号可作为跨内容子目录的强作品边界，其他证据不足的路径保持物理目录分组。卡片显示名称、总数、新增数和示例标题；有新增、较新、偏长音频的位置优先，系统提示目录和全为一分钟内短音频的位置降级到“全部位置”。没有位置元数据时归入“其他音频”，同名位置补充上级名称。

自动发现和文件夹持续扫描都只收录音频。视频只允许用户通过单文件选择明确导入，本轮没有来源级视频发现开关。文件夹扫描会静默登记媒体与外挂字幕的匹配关系：未收录内容只保留来源候选；用户确认收录内容时，全部已匹配字幕立即转为应用自有文字轨；已收录内容后来发现的新字幕也在来源刷新后立即转为自有文字轨。扫描、选择和完成反馈都不显示字幕状态，单个字幕失败不阻塞媒体导入或其他字幕处理。

非作品来源详情默认进入“新增”范围并勾选待添加音频，也可切换“全部”，选择已收录内容追加到其他歌单。明确位于平行 WAV / MP3 目录且除扩展名外文件名相同的待添加音频，初始只勾选 WAV；两份物理文件仍完整展示，用户可以改选 MP3 或同时选择，无法严格配对时维持全部勾选。后台刷新期间，用户尚未修改选择时按相同规则同步新结果；一旦用户手动勾选、全选或取消全选，本次详情不再自动改变选择。列表按标题/文件名自然排序，导入按当前顺序追加；取消勾选不改变待添加状态，只有单项更多菜单的“不再推荐”写入忽略。底部固定显示选择数量、目标摘要和“将 N 项加入 M 个歌单”；成功后停留在来源详情，刷新新增数，不自动播放，并显示添加结果及“查看全部”“完成”。新增范围为空时必须呈现明确完成状态，不能只留下空白列表。

路径包含稳定 RJ 编号且能够形成可信发行边界时，来源详情切换为作品导入：以作品名为主身份、RJ 编号为辅助身份，展示去重后的完整作品清单、正篇版本、特典和格式摘要，不展示歌单目标、物理文件夹树或逐文件复选框。作品名依次使用目录证据和共同 Album 标签，纯格式、音质或 SE 目录不得成为作品名；仍只能得到 RJ 编号时允许用户在导入前修改。已导入作品也可重命名，重新扫描和更新不得覆盖用户标题。严格对应的 WAV/MP3 是同一 Content 的多个 locator，播放时默认优先 WAV；SE 有无等语义变化形成不同的完整正篇版本，未归入语义版本的特典作为共享区段。确认操作只提供“收录整部作品”，完成后全部版本、特典和格式 locator 都由 Work 持有；系统自动选择标准版、其次 SE 版、再次首个可用版本作为当前播放版本。用户以后在作品详情直接整套切换播放版本并从具体段落开始播放。旧版已经按普通歌单收录的 RJ 内容不做自动吸收；需要作品模型时删除旧歌单并重新导入即可。

非作品批量导入必须选择至少一个真实歌单并支持多选。从真实歌单详情打开 Import Hub 时，本次会话优先以当前歌单作为来源导入和单文件导入目标，且不覆盖该来源的长期目标偏好；从中央 Logo 等通用入口打开时，来源首次默认选择默认收藏，成功后记住该来源最后确认的目标集合，下次恢复仍存在的目标，否则回退默认收藏。默认收藏为唯一选择时，首次选择普通歌单会替换它，面板必须说明这一行为；之后可以继续多选或显式重新加入默认收藏。目标面板实时显示确认目标数量，可当场新建歌单并自动选中。新内容加入全部目标；已收录内容只做归属并集，不移除原归属，也不重复插入。

单文件音频或视频从歌单上下文进入时直接加入当前歌单，否则加入默认收藏，并立即播放。启动系统文件选择器时 Import Hub 保持原页面和状态；用户取消后原样返回，读取或导入失败时留在原页面显示明确错误，只有成功后才关闭并进入播放。外部 `ACTION_VIEW` 仍只临时播放，不自动收录。来源是扫描授权与刷新边界，不是歌单；设备目录不会复制成真实歌单或额外授权 Source。

## 4. 播放列表

“播放列表”页面只有一个 Current Queue，数据与 Player 的队列对齐。支持选择播放、拖动重排、移除、清空和当前项标识。队列内同一 `contentId` 唯一，重复加入不追加，只提示“已在播放列表”。

队列连续播放、MediaSession、后台播放、耳机/蓝牙控制和 Sleep Timer 是固定行为，不在设置页暴露开关。Sleep Timer 使用停止条件编辑器：时长由小时/分钟滚轮自由设置，也可选择当前内容结束或多项播放列表结束；滚动只编辑，显式开始或重新计时后才生效。编辑器记住本次播放服务中的上次设定时长。已开启状态只显示“已开启”，播放器与 Glow 均不展示剩余时间、预计停止时间或持续倒计时。

## 5. 配置

配置页只有一套完整的 `SyncTextConfig`，顶部切换“翻译模型配置”和“语音识别”。不向用户展示 Scheme、Attempt、Task Queue、Token、Hash 或技术结果详情。内部仍使用稳定配置 ID 关联后台审计与 attempt snapshot。

翻译配置提供协议选择、可编辑的 Base URL、自动发现的模型选择、思考强度、API Key、目标语言和展示模式。思考强度使用可拖动并吸附的四档选择器“关 / 低 / 中 / 高”，默认关闭；产品不暴露 `xhigh`、`max` 或 token budget，协议适配器把统一档位翻译为各提供商参数。官方示例只展示服务根地址或 `/v1` 地址；用户不需要填写 `/responses`、`/chat/completions` 或其他资源路径，应用根据协议在内部补全。Base URL 或协议变化后静默尝试拉取可用模型，不提供刷新按钮；服务不提供模型目录时仍允许直接填写模型。用户可以发送一个低额度测试请求，确认所选协议、地址、模型、思考强度和 Key 真正可用。每次生成 attempt 固化提交时的思考强度，后续配置变化不影响正在执行的任务。翻译适配器必须显式发送所选思考配置并限制单次输出预算，不能把长时间思考伪装成网络等待。Key 由 Android Keystore 加密保存，Endpoint 必须经过 HTTPS 与主机校验。

ASR 配置先选择提供商，再选择该提供商的模型；OpenRouter 提供 Whisper large-v3 与实验性的 Qwen3 ASR 1.7B，并保留可编辑的 Base URL。Grok STT 已因产品音频识别质量不佳而退出可选列表，历史配置回退到 Whisper large-v3。本项目对 OpenAI 官方提供商当前只开放 Whisper-1，固定使用官方 `/v1/audio/transcriptions` multipart 上传协议，不复用 OpenRouter 的 JSON 音频协议。GPT Transcribe 等只能返回纯文本、不能返回可用时间轴的模型不进入可选列表；未来只有在官方提供时间轴后才重新评估。ASR 请求按提供商共享传输边界，但每个模型由独立适配器固定请求契约、时间轴解析和响应正规化；Qwen3 ASR 1.7B 固定请求 `verbose_json` 的 segment 时间戳，并把 OpenRouter 返回的语言全名映射为 BCP-47。用户可以发送一个极短的测试音频确认连接，测试不会创建同步文字结果。

生成自动使用当前配置：已有文字优先翻译，没有文字才执行 ASR；只有多音轨等真实歧义才请求选择。完整 ASR 时间轴在正式发布前固定经过 Source Preparation：代码先移除明确标记的声音事件，并把版本化的 Whisper 污染模式作为可疑 flag；配置了翻译模型时再以内部固定的低思考专属全量扫描生成稀疏 `DROP` / `REPLACE` patch 和目标语言无关的精简 `SourceContext`，该档位不继承用户为翻译选择的思考强度，也不增加产品开关。提供商以明确的 400/422 响应拒绝 `reasoning` / `thinking` 控制参数时，只允许一次不携带该参数的兼容重发；超时、空输出和普通模型错误不触发该重发。未配置模型或扫描失败时以确定性结果降级完成。该阶段不新增 cue、不改变时间、不拆分合并；`DROP` 只让相应时段成为字幕空白。翻译只读取处理后的 final source revision 及冻结 `SourceContext`，不再修复 ASR，也不由并发批次反向维护记忆。简中翻译会把非词汇语气标记、网络速记和其他表达性符号自然化为中文措辞或标点，避免重复情绪表达和模型新增的括号式说明；真实原文括号仍保留。

单个 ASR 窗口允许没有语音并以空时间轴继续，整个媒体都没有可用 cue 时明确提示“未检测到可转写语音”，不归因于提供商或网络故障。任务默认只使用非计费网络；等待计费网络许可时就地说明原因，并允许用户仅为本次任务授权。临时网络错误使用共享退避与抖动；设备没有 validated network 时进入可自动解除的等待，而不是要求用户手动重试。同步文字页提供暂停、停止生成与重试，不出现全局任务抽屉。暂停立即取消当前网络或媒体处理，保留任务并允许稍后从 checkpoint 继续；恢复时替换可能残留的系统作业并重新调度。应用回到前台时核对可运行任务与 Android 后台作业，系统作业已消失时自动补调度，不能让任务永久停留在“等待”。停止生成将本次任务置为终止状态，保留已完成的同步文字 checkpoint，释放后台执行并允许其他任务继续，不删除原媒体或配置。

## 6. 设置

设置只负责 Glow 窗口/文字/控制亮度、字号、垂直位置、预设与首次校准，以及音频权限状态和关于。应用不请求或展示设备视频库权限；系统栏隐藏、队列连续播放等固定行为不做可选项。

Glow 为纯黑、安全 Insets、独立亮度；双击分区、长按临时控制、5 秒退场保持现有行为。Glow 只在媒体实际播放时保持屏幕常亮；暂停后立即释放常亮但保留当前文字，播放结束、播放错误或 Sleep Timer 触发后立即清空全部来源的文字并保持纯黑，由系统按既有超时策略熄屏和锁屏。Glow 返回 Normal Player，再返回原一级页面。

## 7. Player 与同步文字

Normal Player 的主体固定为“上一句弱化 / 当前句主视觉 / 下一句弱化”，不显示假封面。顶栏只保留返回、标题和低频操作菜单；菜单只处理当前内容的同步文字与“我的内容”归属，不提供添加其他内容，重新选择媒体只在播放失败时原位出现。底部只常驻进度、上一项 / 后退 10 秒 / 播放 / 前进 10 秒 / 下一项、速度、Sleep Timer、播放列表和进入 Glow。随机与循环进入播放列表面板，校准不在播放器常驻，字幕时间偏移藏在同步文字面板。

播放器不常驻同步文字“管理”入口：没有文字时，字幕舞台只显示“生成同步文字”；已有可翻译原文时，只在舞台边缘显示翻译图标。动作启动后原位显示不确定态圆环；任务入队后不显示推算百分比，而是显示可验证的内核事实。没有文字可承载时使用较大的分段圆环表达真实 ASR work unit：多段任务的圆心显示准确的已完成数 / 总数，单段任务不显示没有解释力的 `0/1`；每段只在开始处理、提交完成或失败时改变状态，旁边或下方说明排队、规划音频、提取、等待识别、准备源字幕、重试或发布。连续 ASR 前缀可以临时展示，完整识别后由准备完成的正式 source revision 无感替换；翻译永远不读取 partial ASR。已有原文的翻译保持紧凑状态，不显示 work unit 圆环，不遮挡当前文字；流中的 reasoning delta 只驱动“模型正在处理”，output text delta 才驱动“正在接收译文”，并可按实际出现的预期 cue ID 显示 `N/M`。真实 delta 同时累计任务级、单调且持久化的近似 `≈ tokens` 活动量，并仅在新 delta 持久化时触发一次短微光；它用于判断连接仍有输出，不表示完成比例、计费 token 或上游 usage，切屏、重试和进程恢复不得归零。这些行在严格批次校验前不视为已完成；重试必须明确显示且不得伪装成连续增长。运行中的任务同时提供暂停和停止生成，暂停状态与失败状态仍可直接停止；停止生成终止任务但保留已完成 checkpoint。低频同步文字入口打开底部面板，概览只展示显示方式、主文字、第二文字、时间校准、重新自动匹配和“重新生成”；译文只提供“重新翻译”和“从声音重新生成”，原文只有一个合理路径时直接开始，不展示模型、任务或版本管理。重新生成自动使用当前配置并冻结本次声音、原文与当前选择；从声音重新生成译文时，同一任务在 ASR 完成后继续翻译。新结果成功前保留并继续显示旧结果，失败不切换；成功后只保留当前版与上一版，上一版沿用现有文字选择器，不另设历史页。点击主文字或第二文字后再进入单一用途的候选列表。所有选择立即生效，不设“完成”按钮，不展示生成产物区、格式名、可用状态或“设为主轨 / 次轨”等实现术语；手动文件入口放在对应文字的候选列表底部。启动成功不再弹出确认对话框。手动导入会读取、解析并规范化 SRT / VTT / ASS / LRC，然后发布为应用自有的 immutable revision；成功后的文字轨不再依赖原 URI 或 SAF 权限。Folder 外挂字幕在对应内容被收录且匹配关系已发现时发布为应用自有 immutable revision；资源接管与主/第二文字选择相互独立，播放器不承担正常的候选物化。内嵌文字仍由 Media3 实时播放，仅在生成任务把它作为固定输入时物化 source revision。生成结果完成后自动成为可选文字轨。

## 8. 数据与迁移

Room 当前 schema 为 v15。`Work`、`WorkPart` 和作品进度独立持久化；`playlist_entry` 统一引用 Work 或 Content；Current Queue 保存可空的来源 Work/歌单入口上下文。v10→v11 保留旧歌单及顺序并迁移为 Content 入口，不自动创建 Work。`playlist.system_role` 继续唯一标识默认收藏。来源卡片由可用音频 locator 的 `sourceId + inferred work root` 动态聚合，RJ 根作为可信作品候选边界。

v7→v8 通过自动迁移保留任务、结果和手测诊断数据，v8→v9 手动把旧虚拟文件夹和单归属成员关系迁移为同名多对多歌单。v9→v10 建立并保护默认收藏；v10→v11 把旧歌单成员无损迁移为 Content 类型 `playlist_entry`，为 Queue 增加来源上下文，作品表保持为空；v11→v12 保存翻译思考强度；v12→v13 新增独立的 `generation_runtime_status`，持久化正在发生的阶段事实，但不改变只按已提交 Artifact 推进的任务进度；v13→v14 为任务快照冻结媒体 locator、输入 source revision/hash 和预期切换的文字轨；v14→v15 新增 `source_preparation_checkpoint`，并在 attempt 中冻结 preparation policy version 与 prompt hash。现有多归属、播放时间、同步文字和忽略状态保持；旧 RJ 不自动吸收，用户可删除旧歌单后重新导入。v6 及其他不兼容版本仍允许破坏性重建。

重建清理应用私有旧字幕缓存、旧 result/checkpoint VTT、孤立凭据文件和旧的 Home shortcut 数据；保留 Settings、用户原始媒体和 SAF 外部字幕文件。数据库不再把 `lastSurface` 当作启动入口；`PlayerSurface` 只管理运行期 Normal/Calibration/Glow 层级。

导入与生成文字统一使用 `CanonicalTimeline`、`TimelineRevision` 和 content-addressed `TextArtifactStore`。Artifact 位于 `noBackupFilesDir/text_artifacts/<kind>/<prefix>/<id>.bin`，ID 是包含 kind、schema、codec 与 canonicalizer version 的完整二进制 envelope SHA-256。Room 只保存 Artifact metadata、不可变 revision、manifest 和 publication pointer，不保存逐 cue 正文。`TimelineRevisionReader` 一次解码当前 publication 为内存 `SubtitleTimeline`；播放进度解析不访问 Room、Artifact 文件或 SAF。

ASR window 与 translation batch 由固定数量的 worker 按序领取，先发布 typed Artifact，再在同一 Room transaction 中登记引用和完成状态；任务进度只按真正提交的完成单元推进，并保持单调。Partial revision 引用连续完成前缀的 WorkUnit Artifact；完整 ASR 交给单个版本化 Source Preparation checkpoint，稀疏 patch 与冻结 `SourceContext` 保存为 `SourcePreparation` Artifact，应用 patch 后的 Final source 使用单个 `FinalTimeline` Artifact；target 保存固定 source revision/hash 的 `TranslationDelta`。显式重新生成使用 task-scoped publication slot；同一任务的重试和恢复继续写入原 slot，不制造新版本，完成发布后再收敛为同语言最新两个候选。翻译输出继续严格校验 cue ID，只在缺失字面量 `cue-` 前缀且补全后唯一命中预期 ID 时本地正规化，不发起额外模型请求。启动恢复只重跑没有已提交 Artifact 的单元；已提交的 preparation checkpoint 按 input hash、policy version 与 prompt hash 复用。启动审计将缺失、损坏或未知版本引用标记为 `MissingArtifact` 或 `Storage / NeedsAttention`，不回读旧 URI，也不静默重发付费请求。不可达 Artifact 与未注册文件使用 24 小时宽限的两阶段 GC；当前 publication、target source pin、任务冻结输入和可恢复任务资产是 GC root。

当前没有导出功能；内部 codec 与 revision reader 保留明确的 exporter 边界，但本轮不增加导出 UI。

核心 UI 接口包括 `MainTab.Playlists`、`WorkSummary` / `WorkDetails`、异构 `PlaylistEntrySummary`、带系统角色的 `PlaylistSummary`、`DiscoveryGroupSummary`、来源目标偏好、`SyncTextConfig` 及对应 Repository 查询/写入。Home projection、物理 Folder projection、瞬时 `pendingImport` 不得成为新 UI 依赖。

## 9. 验收
