# VortexCue / 荧荧产品指南

> 状态：当前唯一的产品与实施指导
>
> 当前阶段：M3 退场式播放垂直切片
>
> 长期背景：[`DOMAIN_CONTEXT.md`](DOMAIN_CONTEXT.md)
>
> 更新时间：2026-08-10

本文定义当前要实现和验收的产品行为。`DOMAIN_CONTEXT.md` 解释荧荧为什么存在，但不自动产生实现要求；研究报告用于提供证据和假设，也不直接覆盖本文。

荧荧是一款 Android-first、OLED-first、sleep-first 的本地内容播放器。它服务的是已经躺下、仍想继续听本地 ASMR、voice work、长视频、访谈、课程或其他长内容，却不再需要整块屏幕持续存在的人。

> **内容继续，屏幕退场；当视觉信息仍有价值时，只让当前同步文字发光。**

字幕不是播放硬门槛，但也不是媒体旁边的可选装饰。它是界面退场后仍值得保留的最小视觉内容，尤其服务跨语言理解、没有听清和需要当前语境的时刻。

## M3 目标

M3 只证明一条完整产品路径：

> **今晚打开这个，明晚从这里继续。**

目标流程是：

```text
首次样片或 Home
        ↓
继续上次 / 打开一个内容 / 打开一个文件夹
        ↓
发现或选择可用同步文字
        ↓
字幕中心 Normal Player
        ↓
界面逐渐退场
        ↓
Glow / 纯黑
        ↓
Sleep Timer / 退出
        ↓
下一次从同一内容、位置和表面继续
```

### M3 完成条件

- 用户不需要扫描整台设备或建立资源库，就能打开一个本地媒体并开始播放；
- 有可用同步文字时，用户能确认当前文字轨、进入字幕中心播放器并进入 Glow；
- 没有同步文字时仍能正常播放和进入退场状态，但产品不把纯黑播放当作主要差异化表达；
- 用户退出后，媒体、位置、文字轨、偏移、显示选择和最后表面可以恢复；
- 上次退出于 Glow 时，Home 通过一次明确操作直接继续 Glow，不必先经过 Normal Player；
- 单文件和明确授权的小文件夹不经过“待整理 → 收录 → 首页内容集”流程；
- 全设备扫描只存在于“更多来源”，不在冷启动前台自动执行，也不阻塞 Home；
- 后台播放、通知、锁屏、耳机、蓝牙和 Sleep Timer 保持可靠；
- 至少完成一次创作者连续七晚真实内容使用，区分一次惊艳与重复习惯。

### M3 非目标

以下能力在获得新行为证据前不扩展：

- ASR、自动翻译和 TransVortex 消费端接入；
- 在线字幕搜索、在线内容目录、推荐和社交；
- Artist、Album、封面、EQ 和完整音乐资料库；
- 全设备扫描、待整理和首页内容集的进一步产品化；
- 复杂 Playlist、Shuffle 和通用播放器功能补齐；
- 视频观看 Surface；
- 完整 transcript 阅读器、字幕编辑器和逐词动画；
- 账号、云同步和商业订阅体系。

现有 Queue、Playlist、Library 和扫描代码不因退出主路径而删除。它们保留为支撑能力，只有真实使用证明必要时才重新提高产品优先级。

## 产品原则

- **意图优先于资产**：先帮助用户播放今晚这一份内容，再考虑管理全部媒体。
- **消费方式优先于格式**：音频和视频都可以是主要通过声音消费的长内容。
- **界面允许退出**：越接近睡眠，产品要求用户观看和操作的内容越少。
- **同步文字是正在发生的内容**：优先显示当前 cue，不默认完整 transcript 更高级。
- **字幕优先但不强制**：有字幕时充分发挥它的价值，没有字幕时播放仍然成立。
- **用户选择优先于算法**：手动选择过的文字轨永久压过自动规则，直到用户主动恢复自动选择。
- **本地与最小授权**：文件留在原位置；单文件、文件夹和系统媒体权限按真实任务逐步请求。
- **资源库是支撑层**：能够扫描不等于用户希望先扫描。
- **播放器能力必须有场景理由**：Continue、快退、Sleep Timer 和媒体控制因睡前任务保留，不因“播放器通常都有”而扩张。
- **低发光而非护眼承诺**：使用“低发光”“减少发光面积”“低环境干扰”，不使用“护眼”“零伤害”或“保证睡眠”。

## 核心内容对象

M3 的长期内部对象是一个可恢复的内容体验单元：

```text
PlayableContentUnit
├─ media
├─ timedTextTracks[0..N]
│  ├─ embedded
│  ├─ sidecar
│  ├─ lyrics
│  └─ generated        future
├─ activeText
│  ├─ primary
│  └─ secondary?       optional
├─ playbackState
│  ├─ position
│  ├─ speed
│  └─ queuePosition
├─ textState
│  ├─ offset
│  ├─ language
│  ├─ manualSelection
│  └─ rejectedCandidates
└─ experienceState
   ├─ lastSurface      Normal / Glow
   ├─ brightness
   └─ controlsLocked
```

用户界面不出现 `PlayableContentUnit`、`Track`、`Session` 或匹配置信度等内部术语。用户只看到：

- 内容；
- 字幕；
- 继续；
- 文件夹；
- 睡眠定时。

现有 `MediaSourceRef + SubtitleAssociation` 可以作为迁移起点。M3 不要求一次性重写全部持久化；允许先通过兼容层支持旧数据，再逐步演进为多文字轨模型。

## 应用结构

```text
首次体验
├─ 体验短样片
└─ 打开自己的内容

Home
├─ 继续上次
├─ 打开一个内容
├─ 打开一个文件夹
├─ 少量最近内容
└─ 更多来源

更多来源
├─ 扫描设备媒体
├─ 已授权文件夹
├─ 已收录 / 已忽略
├─ Playlist
└─ 来源管理

Normal Player
├─ 当前字幕语境
├─ 基础播放控制
├─ 字幕轨与同步
├─ Queue 与 Sleep Timer
└─ 进入 Glow

Glow
├─ 当前同步文字
├─ 字幕间隙 / 无字幕纯黑
├─ 沉浸锁定
└─ 临时操作
```

M3 最少只需保存一个可继续的最后内容。少量最近内容不是 M3.1 的完成门槛，不应为了它重新引入完整资源库首页。

## 首次体验

首次启动不先请求全设备媒体权限，也不要求建立资源库。

主路径使用一份可合法随应用分发、长度约一分钟的样片，直接证明：

```text
声音和时间继续
        ↓
完整播放器退场
        ↓
只剩当前同步文字
        ↓
字幕间隙回到纯黑
```

微光亮度校准嵌入第一次样片 Glow，不建立独立的多步骤设置向导。目标是“清晰、舒适、不费力”，不是越暗越好。

用户可以跳过样片并直接打开自己的内容。首次样片、亮度校准和打开文件都不得依赖全盘媒体权限。

## Home 与继续

Home 首先回答“今晚继续什么”，而不是“设备里拥有什么”。

### 继续上次

继续区域至少显示：

- 内容标题；
- 上次位置；
- 当前字幕语言或“无字幕”；
- 上次表面是 Normal 还是 Glow；
- 当前文件不可用时的明确恢复状态。

应用冷启动本身不自动播放。用户点击“继续”是明确播放动作：

- 上次表面为 Glow 且媒体、文字关系仍有效时，直接恢复 Glow；
- 上次表面为 Normal 时，恢复 Normal；
- 媒体或字幕不可读时进入可解释的修复流程，不静默丢失字幕；
- 不要求用户先重新进入资源库或重新收录内容。

### 新内容入口

Home 的新内容一级入口按以下顺序存在：

1. 打开一个内容；
2. 打开一个文件夹；
3. 更多来源。

“扫描本机”不得成为首次空状态的主 CTA。

## 内容进入路径

### 打开一个内容

单文件是最快的高意图路径：

```text
选择媒体
   ↓
恢复已记忆关系
   ↓
发现内嵌文字轨
   ↓
使用已选外挂字幕，或按需手动选择
   ↓
Normal Player
```

- 音频和视频均可打开；视频只提供音轨、时间和文字轨，不创建观看 Surface；
- 单文件打开后直接形成可恢复内容，不进入待整理；
- 没有字幕不阻止播放；
- 单文件授权不能可靠枚举相邻文件，需要自动发现外挂字幕时再邀请用户选择包含内容的文件夹；
- 用户以后可以在播放现场查看、更换、移除或恢复自动字幕选择。

### 打开一个文件夹

明确授权的小文件夹是系列内容和外挂字幕的自然组织层：

```text
选择文件夹
   ↓
扫描这个授权范围
   ↓
发现媒体和文字轨
   ↓
建立高置信关系
   ↓
立即可以播放
```

- 不经过待整理、收录和首页内容集选择；
- Folder 是内容体验单元的集合，不自动等同完整 Library；
- 同目录完全同主文件名可以高置信关联；
- `.zh`、`.en`、`.ja`、`.forced`、`.sdh`、`.cc` 等后缀作为语言或角色信息保留；
- 多个候选全部保留，不选择“最短文件名”后丢弃其他轨；
- 不明确的候选只建议，不自动激活；
- 深层或大型目录必须避免阻塞 Home，并提供可见的扫描状态和取消能力。

### 更多来源与资源库

全设备 MediaStore 扫描、候选整理、收录、忽略、Playlist 和来源管理继续存在于“更多来源”。

只有广泛扫描继续使用：

```text
扫描发现
→ 候选整理
→ 收录或忽略
```

M3 不在冷启动时自动执行全设备扫描，也不递归重新检查全部授权文件夹后才显示 Home。冷启动只恢复缓存状态并验证当前会话所需资源；重扫由用户明确触发，或在进入对应来源时以不阻塞主路径的方式执行。

广泛扫描仍遵守：

- 发现不等于收录；
- 视频默认不选；
- 已忽略内容不反复打扰；
- 移除应用内条目不删除原文件；
- 部分媒体权限范围必须清楚可见；
- MediaStore 字幕索引只能作为补充发现来源，不作为全部文字关系的真相。

## 同步文字发现与选择

字幕发现和字幕激活是两个不同决定：

```text
发现文字轨
    ↓
判断它是否属于当前媒体
    ↓
建立候选关系
    ↓
判断用户现在要看哪一轨
    ↓
激活 primary / secondary
```

优先级如下：

| 来源 | 自动建立关系 | 自动激活 |
| --- | --- | --- |
| 用户此前手动选择 | 是 | 是，最高优先级 |
| 容器内嵌文字轨 | 是 | 明确 default 或符合已知语言偏好时 |
| 同目录完全同 stem 外挂字幕 | 是 | 唯一候选且无手动选择时 |
| 带语言/角色后缀的同名字幕 | 全部保留 | 有明确语言偏好时，否则询问 |
| 可解释的剧集或版本候选 | 只建议 | 否 |
| 模糊文件名或跨目录候选 | M3 默认不出现 | 否 |

每条文字轨至少能够表达：

- 来源：内嵌、外挂、歌词或未来生成；
- 格式和 URI；
- 语言、名称和角色；
- 是否 default、forced、SDH/CC；
- 匹配依据；
- 是否由用户手动选择；
- 是否曾被用户拒绝；
- 当前是否可读和可解析。

M3 保留现有 SRT、LRC、WebVTT、ASS 和 SSA 外挂字幕解析。内嵌文本字幕应接入同一时间轴；图形字幕不应伪装成可用于 Glow 的文本轨。

自动关系读取或解析失败必须显示可恢复状态，并允许重新选择。已有字幕时，Normal Player 仍必须提供查看、切换、更换和移除入口。

## Normal Player

Normal Player 是用户确认内容、理解当前语境和进入退场状态的地方，不复制传统音乐播放器的封面中心布局。

字幕区域按以下层级组织：

```text
上一句          弱
当前句          主视觉
下一句          弱
```

M3 目标能力：

- 当前 cue 与播放时间严格联动；
- 上一句、当前句和下一句提供必要上下文；
- 支持重听当前句或点句跳转；
- primary / secondary 可以独立选择和显示；
- 主次语言拥有独立但克制的视觉层级；
- 字幕 offset 可以调整和重置；
- 当前已有字幕时也能直接管理文字轨；
- 字幕缺失或失败时给出明确的添加或修复动作；
- 进入 Glow 是有同步文字时的主要退场动作。

完整可滚动 transcript、全文搜索和逐词高亮不是 M3 完成条件。它们只有在真实长内容使用证明上下文浏览不足时再进入范围。

普通播放器仍保留：

- 标题与必要元数据；
- 可拖动进度；
- 播放或暂停、快退、快进和上下项；
- 倍速；
- Queue；
- Sleep Timer；
- 返回 Home。

视频容器只播放音轨并驱动文字时间轴。产品不提供视频观看界面。

## Glow

Glow 不是普通播放器隐藏控件后的皮肤，而是退场体验的沉浸表面：

- 有同步文字时只显示纯黑背景和当前 cue；
- primary / secondary 按用户选择显示，不强制双语；
- 字幕间隙不填充装饰、封面、频谱或提示；
- 没有同步文字时纯黑仍是合法退场状态；
- 无字幕 Glow 可以保留控制能力，但不取代“只让字幕发光”成为主要产品表达；
- 默认处于沉浸锁定，普通单次触碰不弹出完整操作栏；
- 左、中、右区域双击分别执行快退、播放或暂停、快进；
- 长按进入临时操作，数秒无操作后重新锁定；
- 临时操作只保留进度、基础控制、Sleep Timer、字幕偏移、文字轨和返回 Normal；
- 退出时保存当前表面，下一次可以直接继续 Glow。

Glow 锁定只防止应用内误触，不冒充系统锁屏或 AOD，也不拦截来电、闹钟和系统安全行为。

窗口亮度、字幕像素亮度和临时控制亮度保持独立。普通界面保持清晰可读，低亮度只属于 Glow。

## 播放、Queue 与 Sleep Timer

`PlaybackService` 内的 Player / MediaSession 是播放状态唯一真相。离开界面、关闭屏幕或应用进程重建时，应用层不建立第二套播放事实。

Continue 至少保存：

- 当前媒体；
- 播放位置和已知时长；
- 倍速；
- Queue 与当前项；
- Repeat / Shuffle 的现有状态；
- active primary / secondary；
- 字幕 offset；
- 最后 Normal / Glow 表面；
- Glow 显示配置；
- URI 可用性和修复信息。

Sleep Timer 至少支持：

- 常用分钟数；
- 当前内容结束后停止；
- 剩余时间；
- 取消；
- 在 Normal 和 Glow 中均可低摩擦进入。

Queue 是本次播放顺序，不是首页信息架构。Folder、Playlist 或用户明确选择的多个内容可以形成 Queue；当前项切换时必须恢复该内容自己的文字轨和显示选择。

## 视觉语言

- 全局使用 OLED 纯黑背景，层级主要依靠排版、间距、透明度和细分隔；
- 不使用大块强调色、彩色卡片、渐变背景和装饰性发光；
- 品牌黄色只用于当前选择、进度、焦点和少数关键动作；
- Logo 只出现在启动、关于或真正需要品牌识别的时刻；
- 主界面不反复解释产品功能或展示操作说明；
- 页面与系统栏尽量融合，减少套用系统模板的感觉；
- 动效以淡入、淡出和克制的位置变化为主；
- 普通界面保持清晰和足够触控面积，低亮度只属于 Glow；
- 每个常驻元素都必须帮助用户开始、理解、控制或继续当前内容。

## 工程边界

工程继续保持单一 `app` 模块，不为目录整齐提前拆分 Gradle 模块。Kotlin 包按职责组织：

```text
app       Activity、应用组合根与系统入口
core      内容体验单元、共享模型与存储格式
library   可选来源、索引、Folder、Playlist 与持久化
playback  MediaSessionService、恢复、Queue 与 Sleep Timer
subtitle  文字轨发现、读取、解析、时间轴与缓存
ui        首次体验、Home、Player 和主题
```

- `PlaybackService` 内的 Player / MediaSession 是播放状态唯一真相；
- 后台播放服务只接受本应用和系统认可的可信控制器，应用私有命令不向外部控制器开放；
- `app` 连接系统入口和功能状态，不重新实现来源、字幕或播放规则；
- Home 不直接拥有扫描和内容关系算法；
- 扫描、匹配、轨道排序、迁移和恢复规则保持为可测试的纯逻辑；
- 当前资源库配置和用户决定必须向后兼容，不进行破坏性清空；
- 媒体文件不复制到应用目录，只有授权、可重建索引、用户关系和小型文字缓存可以持久化；
- 只有出现真实构建、隔离或复用需求时才增加 Gradle 模块。

## M3 实施顺序

### M3.0 规格与基线

1. 以本文替换资源库优先的当前规格；
2. 还原并记录一次产生强烈正向体验的 Golden Session；
3. Golden Session 至少记录近似版本、内容类型、文字轨、单双语、亮度、设备、距离、环境光和退出后的感受；
4. 真机验证开始时建立 M3 记录，不把计划预先写成“已验证”。

### M3.1 恢复核心路径

1. 保存并恢复 `lastSurface`；
2. Home 将继续、打开内容和更多来源按意图重新排序；
3. 上次处于 Glow 时，一次操作直接继续 Glow；
4. 单文件不经过资源库整理即可播放和恢复；
5. 冷启动不执行阻塞式全设备扫描；
6. 先复用现有外挂字幕、Normal Player、Glow、MediaSession 和 Sleep Timer；
7. 不在这一阶段删除 Library、Queue 或 Playlist。

M3.1 完成后立即开始真实夜间使用，不等待字幕模型全部重构。

### M3.2 建立文字关系

1. 引入兼容旧数据的 `PlayableContentUnit` 或等价领域模型；
2. 从单一字幕附件演进为 `0..N` 文字轨；
3. 接入内嵌文本字幕；
4. 保存语言、角色、来源、匹配依据和手动选择；
5. 恢复 primary / secondary 显示；
6. 为已有字幕提供直接查看、更换、切换和移除；
7. 让解析失败和 URI 失效可见、可修复；
8. 为轨道排序、手动优先和恢复迁移增加单元测试。

### M3.3 简化 Folder

1. 明确授权的小文件夹直接生成可播放内容；
2. exact 和语言后缀候选全部保留；
3. 不再要求待整理、收录和首页内容集；
4. Folder 内有限顺序播放形成 Queue；
5. 切换下一项时恢复每项自己的文字关系；
6. 广泛资源库继续留在“更多来源”。

### M3.4 首次体验

1. 加入可合法分发的短样片；
2. 在样片第一次进入 Glow 时完成亮度校准；
3. 不在价值证明前请求广泛媒体权限；
4. 样片结束后直接提供“打开自己的内容”。

### M3.5 行为验证

先完成创作者连续七晚使用，再邀请少量严格筛选的目标用户。

每次至少记录：

- 使用的真实内容类型与来源；
- 音频还是视频；
- 是否有同步文字及语言关系；
- 从哪里进入；
- 是否主动选择 Glow；
- 与直接锁屏相比如何选择；
- Glow 中实际使用了哪些控制；
- 因为什么退出；
- 第二晚是否继续；
- 是否主动加入第二、第三份内容。

北极星信号是：

> **Own-content repeat Glow sessions**

即用户在没有研究员推动的情况下，用自己的内容第二次、第三次主动进入 Glow。

## 验证与决策

### 自动化验证

改动相关范围至少覆盖：

- 文字轨匹配和排序；
- 手动选择压过自动规则；
- 被拒绝候选不会重新自动激活；
- 旧字幕关联向新模型迁移；
- Queue 切换恢复每项文字关系；
- `lastSurface`、位置、offset 和显示状态恢复；
- 广泛扫描不会由普通冷启动触发。

### 真机验证

涉及以下行为必须使用真实 Android 设备：

- 单文件和 SAF Folder 授权；
- 内嵌与外挂文字轨；
- 后台 MediaSession、通知、锁屏、耳机和蓝牙；
- 进程重建与 URI 失效恢复；
- Normal → Glow → Continue；
- OLED 纯黑、字幕 gap 和亮度；
- Sleep Timer 与内容结束；
- 大 Folder 扫描的取消和非阻塞表现。

### 决策分支

- **Go**：用户理解它与锁屏、视频播放器的区别，并用自己的内容重复进入 Glow；
- **Rework A**：喜欢 Glow，但大量内容没有字幕，下一步验证 ASR、TransVortex 或翻译供给；
- **Rework B**：喜欢睡前播放但很少看字幕，继续强化 sleep-first，字幕保留为差异能力；
- **Rework C**：Folder 使用频繁但管理仍重，继续简化 Folder，不深化全库；
- **No-Go / 重新定位**：充分体验后仍普遍选择直接锁屏，或 Glow 只产生一次新奇而没有第二次使用。

在完成 M3.1 的真实夜间使用前，不开始 M4，也不以更多案头研究替代行为验证。
