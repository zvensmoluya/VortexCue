## 1. 范围与已确定边界

- 当前目标用户以手机为主；平板、折叠屏和其他大屏设备不是当前目标用户。
- 大屏只要求基本兼容：能够启动、播放和退出，不为大屏单独设计前台播放信息架构。
- VortexCue 不做专注锁机应用，不自动开启或修改全局 DND（Do Not Disturb / 勿扰模式）。
- 不请求 `ACCESS_NOTIFICATION_POLICY`，不创建 `AutomaticZenRule`，不控制其他应用的通知样式。
- Glow 是应用内的低发光、防误触播放页，不是系统锁屏、AOD 或安全锁。
- 应用可以控制自己的方向、系统栏和媒体通知；整机通知、来电、闹钟和电源键行为仍由系统与用户决定。
- 已采纳：点击 Continue 是明确的恢复并开始播放动作；若上次在 Glow，直接恢复 Glow；冷启动本身不自动播放。
- 已采纳：字幕准备按“内嵌 → 已记忆关系 → 已授权 Folder 发现 → 手动选择”回退；已有用户选择仍拥有最高激活优先级；无字幕不阻止播放，但不主推无字幕 Glow。
- 已采纳：手机默认竖屏，不跟随重力传感器自动旋转；横屏只能由应用内明确操作进入。
- 已采纳：加入可开关的锁屏隐私封面，第一版以中性占位图替换系统锁屏媒体卡封面为目标；这不是 DND、系统锁、截图保护或完整元数据脱敏承诺。
- 版本边界：当前 `compileSdk` / `targetSdk` 为 37，即 Android API 37 / Android 17 的构建与兼容目标，不是“旧手机系统版本 37”。Android 17 在 `smallest width >= 600dp` 的大屏上会忽略方向锁定 API；这与“大屏只做基本兼容”的产品范围一致。参见 [Android 17 方向与可调整大小变更](https://developer.android.com/blog/posts/prepare-your-app-for-the-resizability-and-orientation-changes-in-android-17)。

## 2. 当前问题清单

状态含义：

- **事实**：代码或已有记录可以直接确认；
- **待验证**：存在明确风险，但还不能称为普遍 bug；
- **待决策**：需要先确定产品行为；
- **已定案**：产品行为已确定，但代码或真机验收可能尚未完成；
- **部分定案**：主方向已确定，仍有一个独立子问题待决策或验证；
- **排除**：当前明确不纳入范围。

### 2.1 代码或设计可以直接确认的事项

| 编号 | 状态 | 问题 | 当前证据 | 可能影响 |
| --- | --- | --- | --- | --- |
| A1 | 事实 | 自己的媒体通知还没有产品级闭环 | 使用 `MediaSessionService` 的默认通知；当前 `MediaMetadata.Builder` 只写标题、艺术家和专辑，没有封面或锁屏隐私开关；见 [`PlaybackService.kt`](../../app/src/main/java/io/github/zvensmoluya/vortexcue/playback/PlaybackService.kt) 和 [`VortexCueApp.kt`](../../app/src/main/java/io/github/zvensmoluya/vortexcue/app/VortexCueApp.kt) | 播放时缺少稳定、低打扰、可恢复的系统播放入口 |
| A2 | 事实 | 首次播放可能被通知权限流程阻塞 | `playWithNotificationPermission()` 在 Android 13+ 先请求权限，回调后才开始播放；见 [`VortexCueApp.kt`](../../app/src/main/java/io/github/zvensmoluya/vortexcue/app/VortexCueApp.kt) | 首次点击播放可能变成权限等待；不同 OEM 可能需要不同兼容策略 |
| A3 | 已定案 | 代码尚未落实手机方向策略 | Manifest 没有 `screenOrientation`，代码也没有方向状态管理；见 [`AndroidManifest.xml`](../../app/src/main/AndroidManifest.xml) | 在实现前，用户横拿手机时页面仍可能被系统旋转 |
| A4 | 事实 | Glow 只隐藏系统栏，没有 Activity immersive 信号 | `MainActivity` 只调用 `WindowInsetsController.hide()` 和旧版 system UI flags；见 [`MainActivity.kt`](../../app/src/main/java/io/github/zvensmoluya/vortexcue/app/MainActivity.kt) | SystemUI 未必把 Glow 视为应尽量减少打断的沉浸页面 |
| A5 | 事实 | Glow 根布局没有完整安全 Insets 处理 | Glow 根 `Box` 使用全屏黑底和普通 padding，没有 `safeDrawingPadding()`；见 [`PlayerScreen.kt`](../../app/src/main/java/io/github/zvensmoluya/vortexcue/ui/player/PlayerScreen.kt) | 底部临时控制、字幕或手势区域可能贴近导航栏、刘海或系统手势区 |
| A6 | 事实 | Sleep Timer 只保存在播放服务内存 | `timerJob`、`timerDeadlineMs` 和 `stopAfterCurrentItem` 在服务销毁时清理；见 [`PlaybackService.kt`](../../app/src/main/java/io/github/zvensmoluya/vortexcue/playback/PlaybackService.kt) | 服务重建或进程异常后，用户设置的定时可能失效 |
| A7 | 已定案 | 打开内容仍可能经过额外准备步骤 | 产品规则已确定为单文件先建立内容并可直接播放，字幕准备是可选/可后置步骤；当前导入对话框仍有旧的媒体、字幕和“开始/应用并播放”分段流程，见 [`HomeScreen.kt`](../../app/src/main/java/io/github/zvensmoluya/vortexcue/ui/home/HomeScreen.kt) | 代码未统一前，高意图用户仍可能先付出整理成本，尚未看到播放价值 |
| A8 | 已定案 | Continue 的代码实现尚未完全统一 | 产品规则已确定为“明确点击即恢复并开始播放”；当前 `onContinue` 主要恢复 Player 页面和表面状态，仍需核对播放启动时序 | 用户第二天可能仍需再次点击或重新进入 Glow |
| A9 | 部分定案 | 普通播放页也会在播放时保持亮屏 | 当前 `destination == Player && playback.isPlaying` 时设置 `FLAG_KEEP_SCREEN_ON`；见 [`MainActivity.kt`](../../app/src/main/java/io/github/zvensmoluya/vortexcue/app/MainActivity.kt)。产品原则要求屏幕逐渐退场，普通播放的亮屏实现仍需按该原则统一。 | 普通播放与 Glow 的“屏幕退场”边界不清楚，也可能阻止用户自然熄屏 |

| B7 | 待验证 | 暂停、字幕间隙和内容结束的退场体验未充分验证 | 规则已写入指南，但真实长内容和夜间连续使用不足 | 暂停后字幕保留/淡出、空档纯黑、结束后 UI 和音频状态 |
| B8 | 待验证 | 低亮度长期使用的 PWM、发热、耗电和残影风险 | M0A 只证明首轮 OLED 物理可行性；见 [`M0A_VALIDATION.md`](M0A_VALIDATION.md) | 多台 OLED、20/60 分钟和不同系统显示设置 |

| B10 | 待验证 | 大文件夹扫描的耗时、取消和状态反馈 | 代码已有取消入口，但设备矩阵不足 | 大目录、深层目录、扫描中退出和再次进入 |
| B11 | 待验证 | 真机媒体格式覆盖不足 | M1 主要使用无声 FLAC；有声媒体、Ogg、AAC、视频容器尚未完整覆盖 | 用真实长内容检查解码、音质、时间轴和耗电 |
| B12 | 待验证 | 锁屏隐私封面可能无法独立于标题和艺术家生效 | Android 13+ 系统媒体通知主要从 `MediaSession` 元数据填充；竞品公开说明只保证缩略图替换，用户反馈仍提出标题泄露问题 | 各目标 OEM 分别检查锁屏、通知栏、控制中心、耳机/车机面板的封面、标题和艺术家 |

### 2.3 已定案产品规则与局部默认值

| 编号 | 状态 | 议题 | 已确认 / 仍需回答 |
| --- | --- | --- | --- |
| C1 | 已定案 | 首页优先级 | Home 优先承载继续上次、打开内容和今晚；资源库管理下沉到“我的内容 / 来源”。 |
| C2 | 已取代（历史结论） | Source、我的内容、Tonight、Queue | 四者是一条联动链而非四个同级页面：Source 是访问范围与权限边界；“我的内容”是用户明确保存的平面列表；Tonight 是本次可编辑计划；Queue 是 Player 的运行时播放顺序。M3 不扩展自建专辑、标签或复杂 Playlist 表面。该模型已于 2026-08-13 被新的 [Tonight / Queue 决策](DECISION_2026-08-13_TONIGHT_IS_CURRENT_QUEUE.md) 取代。 |
| C3 | 已定案 | 字幕进入路径 | 按内嵌 → 已记忆关系 → 已授权 Folder 发现 → 手动选择回退；已有用户选择不被静默覆盖。 |
| C4 | 已定案 | 无字幕内容 | 无字幕仍可播放和进入低干扰状态，但不把无字幕 Glow 作为主要 CTA。 |
| C5 | 已定案 | Continue 语义 | 用户明确点击后恢复位置、队列、字幕/偏移和最后表面并开始播放；Glow 直接回 Glow；冷启动不自动播放。 |
| C6 | 部分定案 | Normal、Glow 与屏幕 | 方向已定为手机默认竖屏、禁止传感器自动旋转、横屏由应用显式控制；屏幕退场原则已定，普通播放亮屏策略需按该原则统一实现并验收。 |
| C7 | 部分定案 | 媒体通知与锁屏隐私 | 提供可开关的锁屏隐私封面，至少替换锁屏媒体卡封面为中性占位图；默认关闭；标题、艺术家、文件名是否同步脱敏仍需验证。 |

已定案的 C1、C2、C3、C4、C5、C6 方向和 C7 最小能力、默认关闭原则已写入当前 `GUIDE.md`。核心信息架构不再有待决策项；剩余内容是 C6 的亮屏实现、C7 的元数据范围，以及媒体通知的实现与真机验证。

DLsite Sound 的官方商店说明把该能力描述为将锁屏缩略图替换为虚拟图片；本项目采用这一最小语义，不把竞品功能扩大解释为全局勿扰或安全锁。Android 官方文档说明，Android 13 及以后系统媒体通知主要从 `MediaSession` 的媒体元数据填充，因此标题、艺术家和封面不能在未做设备矩阵前假定可以彼此独立脱敏。参见 [DLsite Sound Google Play 官方说明](https://play.google.com/store/apps/details?hl=ja&id=jp.co.eisys.dlsitesound)、[Android Media3 后台播放与通知](https://developer.android.com/media/media3/session/background-playback) 及 [`research2.md`](../reference/research2.md)。

## 3. 剩余讨论与验证顺序

核心信息架构和会改变产品身份的主方向已经收敛，剩余事项集中在局部默认值、代码统一和设备差异：

1. **A9 / C6 子问题：普通播放的亮屏实现**。按“内容继续、屏幕退场”原则统一 Normal 与 Glow 的亮屏边界，并确认电源键与系统超时行为。
2. **C7：锁屏隐私元数据**。验证标题、艺术家和文件名是否需要在锁屏、通知栏、控制中心分别进一步脱敏。
3. **A1、A2、B1：媒体通知实现与权限时序**。先实现自己的媒体通知，再用 Pixel、vivo、Xiaomi、Samsung、OPPO 做锁屏、通知中心和控制中心矩阵验证。

B 类事项应按真实设备验证，不应先用产品讨论替代实测。

## 4. 当前不纳入范围

- 全局 DND、`AutomaticZenRule`、修改其他应用通知；
- Notification Bubble 和全屏通知；
- AOD、真正系统锁屏、阻止电源键；
- 大屏专用布局和大屏横屏体验；
- Artist、Album、封面生态、EQ、完整音乐库和复杂 Playlist；
- ASR、自动翻译、在线字幕和云同步，除非后续研究证明“缺字幕”是主要流失原因。

## 5. 验证限制

本轮只完成代码、仓库文档和已有真机记录的汇总，没有新增代码修改或新的设备结论，也未实现锁屏隐私封面。后续涉及播放、通知、系统栏、方向、亮度和生命周期的判断，仍需按照 [`ANDROID_DEVICE_VALIDATION.md`](ANDROID_DEVICE_VALIDATION.md) 在真实 Android 设备上记录。
